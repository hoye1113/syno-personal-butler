# Vault 信息密度与中文写作画像

## 密度不是长度

每一章至少保住一个明确命题，并有机制、证据或案例支撑。长度只用于发现异常压缩，不作为主要验收指标。

| 层 | 必须保留 | 失败信号 |
|---|---|---|
| 主张 | 作者具体判断了什么 | 只写主题，不写判断 |
| 机制 | 为什么成立、怎样运转 | 只给结论 |
| 证据 | 数字、案例、demo、原话 | 抽象总结替代事实 |
| 张力 | 条件、反例、限制、争议 | 把有限判断写成绝对真理 |

关键数字必须带上下文；demo 保留输入、动作、结果和限制；编辑新增内容必须能与来源原话区分。删寒暄、广告、重复和时间顺序噪声，不删事实、机制和限定条件。

## 中文画像

- 用具体动词，不写“进行讨论、做出决定、提供支持”。
- 一段只推进一次，不用换词重复同一论点。
- 不宣告深度，不写“更深入地说、值得注意的是、某种程度上”。
- 少用“此外、另外、不仅而且”；能顺着说就顺着说。
- 抽象名词换成具体的人、动作、工具和场景。
- 默念每段；卡壳就整段重写，不逐词修补。

## 收录自检

- 每章能否用一句具体判断概括？
- 判断后是否有机制、数字、案例或 demo？
- 原素材的限制和反例是否还在？
- 是否出现来源中没有、又未标注为编辑新增的内容？
- 摘要是否只负责导航，正文是否足以支持未来检索和讨论？

## B 站专栏精华提炼

必须保留：核心命题、因果机制、方法框架、有解释力的案例、带上下文的数字、限制与反例、真正推动论述的现场问答。

默认删除：摘要与重点速览重复、章节预告、寒暄串场、展位和产品导流、关注提示、同义复述、无知识增量的例子、评论与平台 UI。图片不读取、不识别、不保存。

判断一段是否应留下：删除后若读者仍能回答“是什么、为什么、怎么用、何时不成立”，默认删除。压缩没有固定比例，也不要求固定章数。

## S级对谈式上下文

S级专栏不是摘要，而是可被人和 Agent 共同加载的上下文包。来源是访谈时保留真实问答；来源是演讲时使用“编者问”组织论述，并标 `reconstructed/editorial`。专栏只有第三方总结时使用“专栏整理”，不得写成讲者本人直接回答。

正文保留 3–6 个真正推进理解的问题。每个问题只承担一个命题，回答至少包含判断与机制；关键章节再保留案例、数字或限制。技术步骤可以作为回答中的列表或代码块，不拆成机械问答。

不强制每章概念表、小结或双语金句。开场负责导航，正文负责语境，`知识连接` 负责复用，`来源说明` 负责追溯。

## 可组合知识关系

S级笔记用以下关系连接其他知识：支持、补充、反驳、限制、依赖、应用于、示例。每条链接必须说明两篇笔记在哪个判断、机制或边界上发生关系。裸 wikilink 只能作为普通正文引用，不能替代 `知识连接`。

讨论时先读取命中章节，再沿类型化关系加载一跳上下文；优先组合一个支持观点和一个限制、反驳或边界观点。这样避免把“相似内容”误当成“完整答案”。

## Agent 引用可信度

- `factual_status: verified`：可以引用，仍须附 source。
- `partial`：使用“笔记整理认为”“原视频中提到”等保守措辞，并披露相关 `unresolved_facts`。
- `unverified` 或旧笔记无 factual 字段：只能作为检索线索，关键事实必须回到原始来源核验。

写得顺、结构完整、带直接引语，都不能替代来源核验。
