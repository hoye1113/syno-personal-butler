# Host-Guest 对谈稿 v4

## 目标

对谈不是第三人称摘要的排版变体。它要保留问题如何改变回答方向、人物如何判断、案例如何支撑判断，以及结论在什么条件下失效。对谈同时是人类阅读界面和 Agent 的章节级上下文。

## 必读来源与路由

- B站 opus/cv：先读 curate 的 B站专栏 v2 SUBDOC。
- 真实专栏问答：`dialogue_fidelity: source`、`question_source: column`。
- Legacy ASR 真实问答：`source/transcript`。
- 演讲或叙述材料重构：`reconstructed/editorial`，提问者只能写“编者问”。
- 多人独立立场：保留 roundtable，不压成单一 Guest。

## 声音安全

- 专栏有真实 Host/Guest：使用可核验姓名。
- 没有真实主持人：使用“编者问”，禁止创造 Moderator 或 Host。
- 未知提问者：使用“现场提问”或“观众提问”。
- 来源是讲者直接表达：可保留讲者第一人称。
- 来源是明确归属的转述：可用第三人称归纳，不伪造引语。
- 来源只是第三方总结：回答角色写“专栏整理”，不得塞进真实人物嘴里。
- 无法判断观点归属：标 partial、降级或拒绝。

## Pass 1

写作前提取主张、机制、数字、案例、限制反例、真实问题、人物与声音依据。每个单元记录来源位置、保留决策和目标章节。关键单元必须在成稿中可追踪；删除项必须是重复、宣传、寒暄或无知识增量内容。

## Dialogue Plan

规划 3–6 个真正推进理解的问题：

```yaml
chapters:
  - chapter_claim:
    question:
    question_type: source | editorial
    answer_units: []
    tension:
    related_concepts: []
```

- 每个问题只承担一个主要命题。
- 问题必须打开机制、选择、冲突、实践或边界。
- 编辑问题不能带入来源没有的事实前提。
- 不用“你怎么看未来”之类空问题，也不用同义问题凑章节。
- 回答至少包含判断与机制；关键章节再加入案例、数字或限制。

## 正文结构

```markdown
# 标题

> 人物、主题、核心问题和阅读导航。

## 开场

## 01 具体问题或判断

**Host / 编者问：** 问题。

**Guest / 专栏整理：** 判断、机制、案例和限制。

## 限制与边界

## 知识连接

## 来源说明
```

纯技术步骤可以放在回答中的列表、表格或代码块，不机械拆成逐步问答。章节标题应能单独作为检索问题。

## 密度规则

- 保留数字的对象、条件、时间和比较基准。
- demo 保留输入、动作、结果与限制。
- 不把可能性改成确定性，不删除否定词、反例和责任边界。
- 不强制固定字数、每章最低长度、概念表、本章小结、双语金句或大总结。
- 小结、概念表、金句只在提供新导航或新知识时使用。
- 删除重复摘要、章节预告、广告、寒暄、同义复述和平台噪声。

## 知识连接

使用“支持、补充、反驳、限制、依赖、应用于、示例”连接 1–3 篇笔记，并解释具体关系。找不到可靠连接时标 orphan，不凑链接。新概念只作为候选，不自动创建。

## 质量门

- 人物身份和声音依据可解释。
- source 与 reconstructed 没有混淆。
- 每章问题独立，回答保留判断与机制。
- Pass 1 的核心主张、数字、案例和限制可追踪。
- 转述没有被包装成直接引语。
- 知识连接有类型和理由。
- 来源说明披露实际读取与跳过来源。
- unresolved 非空时不得报告 complete。

## 输出边界

B站同一 BV 只保留一篇 canonical，不另建 `- 对谈稿.md`。新建 MOC、新 tag、概念笔记或覆盖 canonical 前必须取得用户确认。
