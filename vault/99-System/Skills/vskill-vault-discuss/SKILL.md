# vskill-vault-discuss

> **核心一句话**：把 vault 变成"可讨论的"——agent 不再是凭空回答，而是基于 vault 内已有笔记进行有据可查的讨论。

## 何时使用

✅ **使用**：
- 用户说"基于知识库讨论 X"
- 用户问"vault 里关于 X 有哪些观点"
- 用户说"对比 A 和 B"
- 用户想"用现有笔记给我梳理 X"

❌ **不使用**：
- 用户问"搜索 X 笔记"——用 grep / glob 即可
- 用户要"写一篇 X 笔记"——用 `vskill-vault-write`（计划中）
- 用户要"收录新笔记"——用 `vskill-vault-curate`（计划中）
- vault 完全没有相关笔记时——直接告诉用户"无相关笔记"

## 可选模式（mode）

通过 `mode` 参数选择不同的讨论风格：

### `mode: summary`（默认，v0.1 行为）

top-K 评分 + 交叉对比，输出"讨论报告"。**适合**：3+ 篇短笔记的横向对比。

### `mode: roundtable`（v0.2 新增）

**触发条件**：vault 内某主题笔记 ≥ 3 篇，且来自不同作者 / 视角。
**借鉴**：ljg-roundtable 圆桌讨论框架（5+ 真实人物 + 张力网络 + ASCII 立场对比图）。
**输出**："圆桌讨论式" 报告——以"立场"为单位组织（不是"笔记"为单位），凸显 vault 内的视角张力。
**适合**：Harness Engineering 这种 OpenAI / Claude Code / IBM 三家观点并存的主题。

### `mode: companion`（v0.2 新增）

**触发条件**：用户想"深入理解 1 篇长笔记"（如 Loock AI 课程章、Anthropic 汇编 1772 行）。
**借鉴**：ljg-read 伴读 4 阶段（全局地图 → 逐段翻译 → 骨架段深入 → 复盘）。
**输出**：4 阶段伴读报告 + 4 阶段术语表 + 终局问题。
**适合**：单篇 ≥ 3000 字的 vault 笔记深度解读。

## 模式：companion 详解（ljg-read 借鉴）

> **核心理念**：不是代读，是陪用户走进去。翻译只是起手式，真正的活儿是让用户撞见自己从没想过的问题。

### Phase 0: 全局地图（一次性）

通读目标笔记（≥ 3000 字），产出三样东西：

1. **一句话摘要** —— 这篇在说什么，一句话锚定
2. **段落分类** —— 三类标注：
   - `[骨]` 骨架段：核心论证 / 核心观点
   - `[肌]` 肌肉段：展开论证的证据、例子、数据
   - `[筋]` 筋膜段：过渡、连接
3. **全文结构地图** —— 论证单元之间的关系，用 ASCII 图或缩进列表

### Phase 1: 逐段翻译推进

节奏因段落分类而异：

- `[骨]` 骨架段：精读。**翻译三层**——直译（信）/ 意译（达）/ 点睛（雅，按需）
- `[肌]` 肌肉段：流读。连续呈现，末尾标注"以上 N 段在支持骨架段 X 的论证"
- `[筋]` 筋膜段：跳读。一句话带过"作者从 A 过渡到 B"

**翻译操作细节**：
- 语义切段：按语义单元重新切（不按原文自然段）。通常原文一个自然段切成 2-3 个语义段
- 术语策略：首次出现给"中文译法 + 英文原词 + 一句话定义"；后续只给中文加括号英文
- 翻译腔免疫：每段默念"汪曾祺会这么写吗"，卡的地方整段重写

### Phase 2: 骨架段深入

#### 注疏（先问后给）

**先问**："这个概念让你想到了什么？" 或更具体的指向性问题。

- 读者能自己连接 → 确认 / 微调，进入碰撞提问
- 读者连不上 → 给一条注疏，三种光选一：
  - **同构**（侧光）：别的传统里谁说了同样的事
  - **对手**（逆光）：最强的反对是什么
  - **源流**（背光）：从哪来，改变了什么

约束：每次只给一条，选杀伤力最大的。

#### 碰撞提问

核心问题：**"作者这段最想说服你接受的一个点是什么？你接受吗？"**

根据读者回应分三条路：
- "说服了" → 压力测试。Agent 找最强反驳
- "没说服，但说不清" → 三步缩小范围：定位（哪句话）→ 分类（不对 / 跳过 / 不接受前提）→ 追一句（能多说吗）
- "没说服，因为 X" → X 是好反驳 / 基于误解 / 已被后文回应（按情况分支）

### Phase 3: 循环与节奏控制

读者表态后 → 回到 Phase 1 下一段。全文读完 → Phase 4。

**三档变速**（用户随时可切）：
- `快进`：扫读模式——每段一句摘要 + 3-5 个关键词
- `默认`：中等交互——翻译 + 结构标注 + Agent 主动 3-4 次对话
- `展开`：深度模式——完整三层翻译 + 苏格拉底式对话，不限时间

**旁逸**（每篇最多 1-2 次）：当 Agent 识别到与其他领域有深层同构时，岔开一笔——"这里的论证结构，和 [X 领域] 是同一个形状"。

### Phase 4: 全文复盘（四步收尾）

1. **理解轨迹**：把读者碰撞历程标回结构地图——哪里通过 / 哪里停留 / 哪里抵抗。不评判，只呈现
2. **读后一句话**（不可跳过）："读完这篇之后，你最想对作者说的一句话是什么？"
   - L0 无话可说 → 伴读失败
   - L1 复述作者 → 及格
   - L2 有判断 → 成功
   - L3 生出新问题 → 优秀
3. **终局问题**：从理解轨迹的最深裂缝中生成一个问题——不期待当场回答，是种子
4. **术语表 + 下一步线索**：
   - 术语表：英文 / 中文翻译 / 本文含义 / 出现位置
   - 下一步线索：这个问题在哪里被继续推进了？给具体的笔记章节，不给书单

### companion 模式的约束

- ❌ 不替代阅读本身 —— Agent 是陪走者，不是代步车
- ❌ 不降低原文碰撞力度 —— 翻译保留原文的力度和温度
- ❌ 不填满所有空隙 —— 留白给读者的大脑自己长出答案
- ✅ 原文始终在场 —— 中英并列（如原文是英文）/ 关键句加引用（中文笔记）
- ✅ 克制 —— 过度注释和注释不足一样有害，点睛层按需触发，旁逸每篇 1-2 次

## 工作流（5 步）

### Step 1：检索（vault-search 优先）
- 首选用 `vault-search.py` 做章节级检索（BM25 + tag 分面，实时算、不靠人维护索引）：
  ```powershell
  python 99-System/scripts/vault-search.py "{topic}" --json --top {max_notes}
  python 99-System/scripts/vault-search.py "{topic}" --tag {细分tag} --top {max_notes}
  ```
- 返回 `文件 § 章节 [tags] + 分数 + 命中片段`，一次拿到 top-K 候选与命中章节。
- `--tag` 做分面过滤；中英混合查询原生支持（CJK bigram + ASCII word）。
- 兜底（vault-search 无命中，或需精确匹配专名/作者）：`grep` 搜 `topic` 在 tags/title/description，`glob` 找文件名，MOC 索引（~15 个）作入口。

### Step 2：评分（top-K 候选）
- vault-search 已给出 BM25 相关度分数，直接取 top `max_notes`（默认 10）。
- 无 vault-search 时回退手工评分：tags 命中 ×3、标题命中 ×5、description 命中 ×2、MOC 链入 ×1。

### Step 3：加载（注意 token 预算）
- 先定位命中章节，不默认加载全文；再沿 `知识连接` 的类型化链接加载一跳上下文
- 默认尝试加入一个支持/补充观点和一个限制/反驳/边界观点
- 单笔记 > 3000 字时优先加载命中章节、相邻论证和限制边界
- 总加载量超过 50k 字时触发"加载警告"，让用户选择

### Step 4：交叉对比
- 提取每篇笔记的"核心观点" / "关键洞察"
- 标注：支持 / 补充 / 反驳 / 限制 / 依赖 / 应用 / 示例
- 冲突时给出来源（笔记标题）
- `verified` 可引用并附 source；`partial` 使用保守措辞并披露 unresolved；`unverified` 只作为检索线索

### Step 5：输出报告
按下方"输出格式"生成。

## 例子

**输入**：
```yaml
topic: "Harness 与 Loop Engineering 的关系"
scope: "02-Resources"
max_notes: 8
depth: deep
```

**预期行为**：
1. 检索命中 "Harness" "Loop" "Engineering" 相关笔记 ~5 篇
2. 加载 [[2026 年 Agent 最重要的工程概念 Harness Engineering]]、[[Loop Engineering 橙皮书 - 花叔]]、[[遇事留痕 - Loop Engineering 的基础 - 魔术师卡颂]] 等
3. 交叉对比：花叔说"Loop = Harness 上一层"、卡颂说"留痕是 Loop 基础"、OpenAI 说"Harness = 文档系统"
4. 输出报告，标注 3 篇笔记的一致性（Loop 是 Harness 之上的元层）+ 视角差异

## 约束

- ❌ 不杜撰笔记中不存在的观点
- ❌ 不引入 vault 外的知识（除非明确告知用户）
- ❌ 不在报告中修改 vault（这是 `vskill-vault-write` 的事）
- ✅ 所有引用必须能 wikilink 追溯到具体笔记
- ✅ 报告本身是**临时输出**，不写入 vault（除非用户明确要求"保存为笔记"）
