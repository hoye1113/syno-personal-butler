### [图的类型](#图的类型)

#### [StateGraph（推荐）](#stategraph推荐)

最常用的图类型，允许你定义自定义的状态结构。

```
import { StateGraph, Annotation } from '@langchain/langgraph';
const StateAnnotation = Annotation.Root({
  // 定义你的状态字段
  userInfo: Annotation<string>(),
});
const graph = new StateGraph(StateAnnotation);
```

#### [MessageGraph（简化版）](#messagegraph简化版)

状态只包含消息数组，适合简单的对话场景。

```
import { MessageGraph } from '@langchain/langgraph';
// 状态自动为 { messages: BaseMessage[] }
const graph = new MessageGraph();
```

**ℹ️ 使用建议**

对于大多数应用，推荐使用 **StateGraph**，因为它提供了更大的灵活性和类型安全性。

### [编译过程](#编译过程)

图在使用前必须经过 `.compile()`，类似于编译代码。这个过程会检查图的连通性。

```
// 构建图结构
const workflow = new StateGraph(StateAnnotation)
  .addNode('input', processInput)
  .addNode('llm', callLLM)
  .addEdge('input', 'llm')
  .addEdge('llm', END);
// 编译图（必需步骤）
const app = workflow.compile();
// 现在可以执行
const result = await app.invoke({ messages: [...] });
```

## [2 状态（State）管理](#2-状态state管理)

状态是 LangGraph 应用的**数据中心**。

### [状态的概念](#状态的概念)

状态具有以下特点：

-   **共享性**：所有节点都可以访问和修改
-   **持久性**：在整个执行过程中保持
-   **类型安全**：通过 TypeScript 提供类型检查

### [使用 Annotation 定义状态](#使用-annotation-定义状态)

```
import { Annotation, messagesStateReducers} from '@langchain/langgraph';
import { BaseMessage } from '@langchain/core/messages';
const StateAnnotation = Annotation.Root({
  // 1. 使用内置 reducer（追加模式）
  messages: Annotation<BaseMessage[]>({
    reducer: messagesStateReducer,
    default: () => [],
  }),
  // 2. 简单替换模式（无 reducer）
  userInput: Annotation<string>(),
  // 3. 自定义 reducer（合并模式）
  metadata: Annotation<Record<string, any>>({
    reducer: (current, update) => ({ ...current, ...update }),
    default: () => ({}),
  }),
});
```

### [Reducers的作用](#reducer-的作用)

Reducers决定了当节点返回状态更新时，如何将新值与旧值合并。

模式

用途

示例

累加

数组追加

`(a, b) => [...a, ...b]`

合并

对象合并

`(a, b) => ({...a, ...b})`

覆盖

直接替换

不设置 reducer

### [状态设计最佳实践](#状态设计最佳实践)

**好的实践：**

```
const StateAnnotation = Annotation.Root({
  messages: Annotation<BaseMessage[]>({
    reducer: messagesStateReducer,
    default: () => [],
  }),
  currentTool: Annotation<string | undefined>(),
  retryCount: Annotation<number>({
    default: () => 0,
  }),
});
```

**应该避免：**

-   使用 `any` 类型（类型不安全）
-   过于复杂的嵌套结构（难以维护）
-   在状态中存储函数或不可序列化的对象（影响持久化）

## [3 节点（Nodes）](#3-节点nodes)

节点是 LangGraph 中的**执行单元**。

### [节点函数签名](#节点函数签名)

```
const myNode = (state: State) => {
  // 1. 读取状态
  const value = state.someField;
  // 2. 执行逻辑...
  // 3. 返回部分状态更新
  return {
    updatedField: newValue,
  };
};
```

### [节点类型](#节点类型)

-   **同步节点**：直接返回结果。
-   **异步节点**：`async/await`，用于 API 调用。
-   **配置化节点**：接收 `config` 参数，用于运行时调整行为。

## [4 边（Edges）](#4-边edges)

边定义了节点之间的**执行流程**。

### [边的作用](#边的作用)

边决定了「执行完这个节点后，下一步去哪里」，是流程控制的核心。

### [边的类型](#边的类型)

#### [普通边](#普通边)

无条件跳转：`graph.addEdge('nodeA', 'nodeB');`

#### [条件边](#条件边)

根据状态动态决定下一个节点：

```
const routeDecision = (state: State) => {
  if (state.needsTools) return 'toolNode';
  return 'answerNode';
};
graph.addConditionalEdges('decisionNode', routeDecision);
```

路由函数返回的字符串必须是已添加的节点名称，或者是 `END`。

#### [带映射的条件边](#带映射的条件边)

当路由函数返回值与节点名不一致时使用映射：

```
graph.addConditionalEdges('classifier', classify, {
  high: 'premiumHandler',
  low: 'basicHandler',
});
```

## [5 完整示例](#5-完整示例)

```
import { StateGraph, Annotation, START, END } from '@langchain/langgraph';
import { BaseMessage, HumanMessage, AIMessage } from '@langchain/core/messages';
import { messagesStateReducers} from '@langchain/langgraph';
// 1. 定义状态
const StateAnnotation = Annotation.Root({
  messages: Annotation<BaseMessage[]>({
    reducer: messagesStateReducer,
    default: () => [],
  }),
  intent: Annotation<'question' | 'chat' | 'unknown'>(),
});
// 2. 定义节点
const analyzeIntent = (state: typeof StateAnnotation.State) => {
  const lastMessage = state.messages[state.messages.length - 1];
  const content = lastMessage.content.toString().toLowerCase();
  let intent: 'question' | 'chat' | 'unknown' = 'unknown';
  if (content.includes('?') || content.includes('什么') || content.includes('如何')) {
    intent = 'question';
  } else if (content.includes('你好') || content.includes('嗨')) {
    intent = 'chat';
  }
  return { intent };
};
const handleQuestion = () => ({
  messages: [new AIMessage({ content: '这是一个很好的问题，让我来回答...' })],
});
const handleChat = () => ({
  messages: [new AIMessage({ content: '你好！很高兴和你聊天。' })],
});
const handleUnknown = () => ({
  messages: [new AIMessage({ content: '我不太确定你的意思，能再说清楚一点吗？' })],
});
// 3. 定义路由
const routeIntent = (state: typeof StateAnnotation.State) => {
  switch (state.intent) {
    case 'question':
      return 'questionHandler';
    case 'chat':
      return 'chatHandler';
    default:
      return 'unknownHandler';
  }
};
// 4. 构建图
const graph = new StateGraph(StateAnnotation)
  .addNode('analyzer', analyzeIntent)
  .addNode('questionHandler', handleQuestion)
  .addNode('chatHandler', handleChat)
  .addNode('unknownHandler', handleUnknown)
  .addEdge(START, 'analyzer')
  .addConditionalEdges('analyzer', routeIntent)
  .addEdge('questionHandler', END)
  .addEdge('chatHandler', END)
  .addEdge('unknownHandler', END)
  .compile();
// 5. 执行
const result = await graph.invoke({
  messages: [new HumanMessage({ content: '什么是 LangGraph？' })],
});
```

## [💡 练习题](#-练习题)

1.  **代码题**：定义一个状态 Annotation，包含一个 `count` 字段（数字类型，默认值 0，reducer 为累加）和一个 `history` 字段（字符串数组，默认空数组，reducer 为追加）。
    
    点击查看答案
    
    `count` 可写为 `Annotation<number>({ reducer: (a, b) => a + b, default: () => 0 })`； `history` 可写为 `Annotation<string[]>({ reducer: (a, b) => a.concat(b), default: () => [] })`。 这样并行更新时也能按预期合并状态。
    
2.  **设计题**：设计一个简单的“请假审批”流程图，包含“申请”、“经理审批”、“人事备案”三个节点，其中“经理审批”需要根据请假天数决定是“通过”还是“驳回”。
    
    点击查看答案
    
    流程可设计为：`START -> 申请 -> 经理审批 -> (通过: 人事备案 -> END, 驳回: END)`。 经理节点根据 `days` 路由，例如 `days <= 3` 自动通过，`days > 3` 转人工审批后再决定通过或驳回。
