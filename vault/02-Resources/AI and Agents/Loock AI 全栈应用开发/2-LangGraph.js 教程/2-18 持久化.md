## [1 为什么需要持久化？](#1-为什么需要持久化)

默认情况下，Graph 运行在内存中。一旦程序结束或服务器重启，状态就丢失了。 持久化允许我们：

1.  **长对话**：用户隔天回来，还能接着昨天的聊。
2.  **人机交互**：Graph 暂停等待用户批准，几天后用户批准了，Graph 能从暂停点继续运行。
3.  **调试/时间旅行**：查看过去的每一步发生了什么，甚至修改过去的状态并重新运行。

* * *

## [3 使用 Saver](#3-使用-saver)

最简单的是 `MemorySaver`（仅内存，重启丢失，适合测试）。生产环境通常使用 `PostgresSaver` 或 `SqliteSaver`。

### [内存持久化示例](#内存持久化示例)

```
import { MemorySaver } from "@langchain/langgraph";
import { HumanMessage } from '@langchain/core/messages';
// 1. 初始化 Checkpointer
const checkpointer = new MemorySaver();
// 2. 编译时传入
const app = graph.compile({ checkpointer });
// 3. 调用时传入 thread_id
const config = { configurable: { thread_id: "conversation-1" } };
// 第一轮
await app.invoke({ messages: [new HumanMessage("Hi")] }, config);
// 第二轮 (状态会自动加载)
await app.invoke({ messages: [new HumanMessage("My name is Bob")] }, config);
```

> \[!TIP\] 只要 `thread_id` 相同，图会在执行前自动加载旧状态，然后把这次输入合并进去。

### [数据库持久化 (Postgres)](#数据库持久化-postgres)

需安装 `@langchain/langgraph-checkpoint-postgres`。

```
import { PostgresSaver } from "@langchain/langgraph-checkpoint-postgres";
import { Pool } from "pg";
const pool = new Pool({ connectionString: "..." });
const checkpointer = new PostgresSaver(pool);
// 首次使用需初始化表
await checkpointer.setup();
const app = graph.compile({ checkpointer });
```

## [4 读取状态与历史（Debug/Time Travel 的基础）](#4-读取状态与历史debugtime-travel-的基础)

### [读取当前状态：getState](#读取当前状态getstate)

```
const config = { configurable: { thread_id: 'conversation-1' } };
const snapshot = await app.getState(config);
console.log(snapshot.values); // 当前 state
console.log(snapshot.next);   // 下一步将执行哪些节点（如果还有）
```

### [遍历历史：getStateHistory](#遍历历史getstatehistory)

```
const history = await app.getStateHistory(config);
for await (const h of history) {
  const checkpointId = h.config?.configurable?.checkpoint_id;
  console.log('checkpoint:', checkpointId);
  // h.values 是当时的 state
}
```

如果你想“回到过去并分叉”，请继续看：[时间旅行](./06-time-travel)。

## [5 线程管理 (Threads)](#5-线程管理-threads)

`thread_id` 是持久化的 Key。

-   同一个 `thread_id` = 同一个对话历史。
-   不同的 `thread_id` = 隔离的对话。

你可以通过 `app.getState(config)` 查看当前线程的状态。

```
const state = await app.getState(config);
console.log(state.values); // 查看当前 State
console.log(state.next);   // 查看下一步要执行的节点
```

### [thread\_id 命名建议](#thread_id-命名建议)

一个常见、好排查的格式：

-   `userId:conversationId`

这样你在日志里看到 thread\_id 就能直接定位到用户和会话。

## [💡 练习题](#-练习题)

1.  **实战题**：使用 `MemorySaver` 创建一个简单的累加器 Graph。
    
    -   第一步：输入数字 5。
    -   第二步：即使不传入任何输入，再次 invoke，Graph 应该能确保持续累加（如果逻辑是读取旧值+1）。
    -   验证：尝试换一个 `thread_id`，确认状态是隔离的。
    
    点击查看答案
    
    编译图时传入 `checkpointer: new MemorySaver()`，状态里维护 `count` 并在节点中执行 `count = (oldCount ?? 0) + (input ?? 1)`。 同一 `thread_id` 第二次调用不传输入也会在上次基础上累加；换新 `thread_id` 会从初始值开始，证明线程隔离生效。
