# Hermes 联合创始人谈如何构建自我改进的 AI 智能体 | Karan Ma

> 这篇专栏整理 Hermes 联合创始人 Karan Malhotra 对开放 Agent 运行环境的解释：模型只是底座，真正决定个人化和长期能力的是上下文、记忆、技能、批评机制与可替换的运行时。
>
> **核心主张：** 自我改进首先是让智能体能正确管理经验和上下文，再把有效经验沉淀为技能、记忆与代码；开放运行框架的价值是把选择权留给用户，而不是把个人积累锁在单一模型里。

> 个性化不靠一句人设提示，而靠记忆、技能、批评机制和清理循环共同积累。
> ——Karan Malhotra（专栏整理）

## 开场

专栏从 Hermes 的定位、对齐和记忆谈到 Sonic 模组演示、开放模型兼容与自我贡献代码。下文以问题驱动重构主要机制，保留“能力释放”与“安全边界”之间的张力；项目性能、下载量和具体演示均未做外部核验。

## 01 对齐不是让模型一直说“你是对的”

**核心判断：** 模型训练得到的高奖励行为可能只是维持“像助手”的表面互动，真正的对齐检验应是能否完成用户任务并在必要时提出反对意见。

**编者问：** Hermes 为什么把反谄媚当作智能体设计问题？

**Karan Malhotra（专栏整理）：** 如果智能体反复附和用户、制造继续对话的动力，它可能是在优化训练奖励，而不是帮助用户完成目标。好的运行环境应允许批评型人格、反例和无上下文的对抗审阅进入流程；用户要把“让我舒服”与“让我看见错误”区分开来。

## 02 运行环境通过上下文改变同一模型

**核心判断：** Hermes 的差异不只在模型选择，而在于它怎样把人格、历史、工具、任务和用户偏好编译成当前上下文。

**编者问：** 为什么切换 Claude、GPT 或 Qwen 后，用户积累的上下文仍然重要？

**Karan Malhotra（专栏整理）：** 模型换了，用户的任务日志、记忆、技能和权限仍可作为更稳定的个人层。Hermes 把这些内容组织成运行时，让底层模型从平台默认目标转向具体用户；个性化不是一条“你是谁”的提示词，而是许多次任务和反馈留下的可检索状态。

## 03 自我改进首先是记忆与技能的治理

**核心判断：** 记忆不应无差别塞进长窗口，技能也不应无限堆积；检索、清理和用户可修改的整理标准是长期可用性的前提。

**编者问：** 一个 Agent 怎样在越用越多的同时避免越用越乱？

**Karan Malhotra（专栏整理）：** 记忆在任务需要时被检索，技能把复杂流程压缩为可调用上下文，Curator 则定期清理冗余内容。用户可以调整整理标准，决定哪些经验值得保留。自我改进不是让模型凭空“变聪明”，而是让一次成功的任务变成下次可以复用、审阅和修正的结构。

## 04 开放框架把模型选择权还给用户

**核心判断：** 当个人数据和工作流长期积累在 Agent 中，运行框架必须支持模型、沙箱与工具的替换，否则个性化会反过来形成供应商锁定。

**编者问：** Hermes 为什么强调开放模型兼容和本地运行？

**Karan Malhotra（专栏整理）：** 开源运行框架让用户可以在 Claude、GPT、Qwen 或本地模型之间切换，按成本、能力和任务要求选择。企业也可以在私有环境中利用自己的操作轨迹做定制，而不必把所有数据交给一个闭源服务商。开放并不等于没有风险，凭证、工具权限和环境切换仍需要明确边界。

## 05 小众领域的长期积累能跨过能力门槛

**核心判断：** 复杂任务的突破不来自一次漂亮生成，而来自智能体学习文档、旧代码和失败经验，并把经验持续写回技能与记忆。

**编者问：** Sonic Chao Garden 模组演示说明了什么？

**Karan Malhotra（专栏整理）：** 他用 Hermes 与 Claude 迁移地图、补写 C/C++ 代码、处理模型绑定、碰撞、NPC、昼夜循环和游戏状态。专栏将关键归因于 Agent 能阅读文档和既有 Mod，并把小众代码库的知识积累下来；这说明“自我改进”的最小单位可以是一个越来越熟悉特定领域的工作环境，而不是一次泛化的模型升级。

## 06 从开源模型到 Agent 自己贡献代码

**核心判断：** 当 Agent 能收集反馈、运行测试并提交改动时，代码库可以成为自我改进的观察窗口，但人仍需定义目标和接受边界。

**编者问：** Hermes 所谓“自己是最活跃的贡献者”意味着什么？

**Karan Malhotra（专栏整理）：** Hermes 的使命从开放模型延伸到让任何人拥有可学习、可使用工具、可创建工具的运行框架。专栏称 Agent 已能根据社区反馈提交改动，成为代码库的活跃贡献者；这更像一个正在形成的反馈系统，而不是自动保证正确的自主开发者。代码审查、权限和回归仍是不可替代的治理层。
