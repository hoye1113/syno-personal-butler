# Restate CEO-每一步每次调用都可靠的Agent系统

> 作者：Giselle van Dongen（Restate CEO）  
> 来源：[B站图文专栏 - Easonlee的AI笔记](https://www.bilibili.com/opus/1250848236447465493)

## 摘要

导读： Restate CEO Giselle van Dongen 讲解生产级智能体为何需要独立的持久化执行层。真正难点不在 Agent SDK，而在让长任务可恢复、可交互、可取消，并能安全扩展到组织级并发。

- 智能体正在成为长期运行进程 [01:05]

从网页式问答、桌面应用式工具调用，智能体正走向异步、持久运行的基础设施实体。SDK 适合快速验证，却不负责连接组织内分布式组件的故障恢复与状态一致性。

- 故障恢复必须回到准确断点 [03:10]

Restate 将执行事件写入日志；研究任务即使运行一周后崩溃，也能从失败步骤继续，而不是重跑全部流程。一次搜索 API 宕机后的重试，正是这种持久化执行的直接收益。

- 人工审批可以暂停数周而不占资源 [07:00]

审批不该靠长连接或不断轮询维持。持久化承诺把等待点保存下来，流程在无服务器环境中可真正暂停；收到 Slack 点击结果后，再从原处解除阻塞并继续执行。

- 会话应建模为隔离的有状态实体 [09:10]

比起固定工作流，虚拟对象更适合持续对话的智能体：它以会话 ID 持有独立状态和处理器，并保证同一会话同一时刻只有一个执行，避免两条消息覆盖记忆。

- 新输入应分流为注入或重启任务 [12:05]

协调器先判断补充消息是否仍与当前任务相关：相关就向运行中的 Agent 发送信号并更新上下文；无关则取消当前执行、沿调用链终止子任务，再以新主题重新开始。

- 把模型调用抽成网关才能治理成本 [15:20]

昂贵新模型上线后，不必重写整个 Agent。将内联模型调用提取为独立网关，可统一加入策略检查、限流和部门配额；智能体通过分布式调用使用它，基础层仍负责韧性与恢复。

## 01 从基础设施到智能体平台

Giselle van Dongen（嘉宾）：大家好。今天要讲的是如何在生产环境中可靠地运行智能体。不讲 E 文件那部分，而是讲清楚要让智能体具备韧性运行能力所需的其他一切。

Giselle van Dongen（嘉宾）：先从基础设施层开始。我想用上周 Andre Karpathy 的一句话来铺垫背景。他指出，我们与智能体和大语言模型的交互方式经历了三个阶段。

Giselle van Dongen（嘉宾）：第一阶段，大语言模型就像一个网站：我们访问它、提出问题，它思考几秒后给出回答。第二阶段开始走向智能体，它变成了一个下载到电脑上的应用，拥有一些可用工具，并能在我们的交互下完成工作。

Giselle van Dongen（嘉宾）：第三阶段则越来越趋向于持久化、异步运行的实体。也就是说，智能体会作为基础设施中的长期运行进程，访问组织内的工具、其他智能体以及上下文。

Giselle van Dongen（嘉宾）：随着应用场景从单个智能体不断发展为连接组织各部分的智能体平台，基础设施层也应该随之演进。

Giselle van Dongen（嘉宾）：目前用于实现智能体的工具中，智能体 SDK、记忆等方面已经有了大量创新。智能体 SDK 非常适合实现概念验证并快速上手，但不一定能帮助你连接组织各处的分布式组件。

Giselle van Dongen（嘉宾）：而要实现更复杂的智能体系统，这些能力其实都不可或缺。这就是下面这一层：你需要额外部署基础设施，编写重试逻辑、恢复逻辑等。把这些真正做好相当复杂，但要让长期运行、有状态、分布式的进程在生产环境中运行，它们又完全必不可少。

Giselle van Dongen（嘉宾）：今天我想介绍一个名为 Restate 的开源框架。你可以把它看成一个灵活且持久的基础，让你能够构建各种后端。它并不是专门为智能体设计的，但智能体本质上也是一种后端，因此同样适用。

Giselle van Dongen（嘉宾）：Restate 的理念源自 Apache Flink——一个流行的分布式流处理引擎，也借鉴了 Meta 核心事件基础设施背后几位前架构师的经验。

## 02 Restate 的核心能力

Giselle van Dongen（嘉宾）：那么，Restate 包含哪些要素？基本上有四个部分。首先，它确保一次智能体运行具备韧性，业内称之为持久化执行。

Giselle van Dongen（嘉宾）：比如，一个智能体运行了一周后崩溃了，我们希望能够恢复它，并让它从失败的准确位置继续运行，而不是从头开始。

Giselle van Dongen（嘉宾）：另一个方面，是并行运行大量并发会话。想象一下同时运行数千个智能体会话，并确保状态始终一致、不同智能体之间互不干扰。

Giselle van Dongen（嘉宾）：再进一步，还要处理智能体之间、智能体与 MCP 服务器及其他工具之间的通信。

Giselle van Dongen（嘉宾）：最后是控制能力。比如，智能体正在做某件你不希望它继续做的事，或者它陷入卡死时，你能够取消或终止执行。

Giselle van Dongen（嘉宾）：你可以这样理解它：Restate 本质上是一台运行在智能体服务前面的服务器。作为独立组件，它有点像消息代理或代理服务器。

Giselle van Dongen（嘉宾）：当有请求发给你的智能体时，Restate 会将请求代理并转发给该服务。从那一刻起，Restate 与智能体之间会保持一条连接，这条连接有点像智能体的生命线。

Giselle van Dongen（嘉宾）：智能体执行任务时，会把事件发送给 Restate，而 Restate 会利用这份事件日志，在发生故障后恢复进程。

Giselle van Dongen（嘉宾）：换个更高层次的说法，它能把应用中的普通函数变成长时间运行、持久化且有状态的函数，而不必自己处理那些复杂工作。

## 03 Slack 深度研究智能体演示

Giselle van Dongen（嘉宾）：今天的演讲主要会以演示为主。我会展示一个连接到 Slack 的研究智能体。

Giselle van Dongen（嘉宾）：假设我们在某家公司工作，希望让所有员工都能使用一个 Slack 智能体。比如进入 Slack 后，我可以在这个频道里问：“AI 最近有什么新动态？”现在来看看它在底层做了什么。

Giselle van Dongen（嘉宾）：回到这里，可以看到 Restate 的界面。它有点像智能体的驾驶舱。你可以看到当前注册的所有智能体，也可以看到当前正在进行的执行。

Giselle van Dongen（嘉宾）：这里就是我几秒前启动的深度研究智能体，我们可以看到它当前正在做什么。它先调用了一个大语言模型，然后通过 Slack 给我发送了答案。

Giselle van Dongen（嘉宾）：第一次大语言模型调用的是规划智能体。它先规划了研究流程，并给出一份想要研究的子主题列表。现在点击这里的“批准”，这样就会解除工作流阻塞，并启动一组并行研究智能体。

Giselle van Dongen（嘉宾）：这基本上就是经典的深度研究工作流：先有一个规划器，然后是一组子研究智能体，最后由写作智能体撰写报告。

Giselle van Dongen（嘉宾）：左侧看到的这份日志，就是智能体发送给 Restate 服务器的事件。如果它在某个时刻崩溃，系统就会利用这份日志，将执行恢复到失败的位置。

Giselle van Dongen（嘉宾）：我在这里注入了一些工具错误。比如可以看到，子智能体先调用了大语言模型，然后开始进行网页搜索；最终其中一次搜索因为 API 宕机而失败。

Giselle van Dongen（嘉宾）：右侧可以看到它经过重试，最终成功完成。它不是从头开始，而是利用日志恢复了执行进度。

## 04 持久化执行与工作流

Giselle van Dongen（嘉宾）：现在来看看代码中的实现。在 Restate 中实现应用的基本单元，是编写 HTTP 处理器，再通过 Restate SDK 让这些处理器具备持久性。

Giselle van Dongen（嘉宾）：这里是我们的深度研究处理器，第一个参数是一个名为 ctx 的 Restate 对象。你可以把它理解为与 Restate 服务器之间的连接。每当我对这个 Restate 对象执行操作，就会有一个事件发送给 Restate。

Giselle van Dongen（嘉宾）：比如刚才调用规划器大语言模型时，底层究竟发生了什么？它是在这里执行这个 Python 函数吗？这只是一次简单的大语言模型调用。我通过把它包装在 Restate run 中，让它具备了持久性。

Giselle van Dongen（嘉宾）：也就是说，如果它在这里失败，无论是两小时后还是两个月后，系统都能准确恢复到这一位置。这就是持久化执行的理念。你始终可以将进程恢复到它原本所在的位置。

Giselle van Dongen（嘉宾）：它也不一定只用于故障恢复。比如，我们需要请人审批某件事，而审批可能要花几周甚至一个月。在这么长的时间里，这个流程必须能够经受重启和重新部署。

Giselle van Dongen（嘉宾）：借助持久化执行，你还可以暂停一个函数，等它能够继续推进时再恢复。以人工审批为例，我们会创建一个持久化承诺，将它保存在日志中，有点像一个暂停点。

Giselle van Dongen（嘉宾）：然后请人工像刚才演示的那样，在 Slack 中点击按钮。等待期间，这个进程实际上会暂停。如果它运行在无服务器环境中，就不会占用函数的执行时间。收到响应后，流程会解除阻塞，并从中断处继续。

Giselle van Dongen（嘉宾）：所以这里看到的有点像一个工作流。它由一系列以持久化方式执行的步骤组成。

## 05 虚拟对象与有状态交互

Giselle van Dongen（嘉宾）：但如果考虑智能体，以及 Karpathy 在推文中的描述，它更像一个长期存在的、有状态的持久化实体，拥有一定的记忆。因此，工作流并不是建模这类对象的最佳方式。

Giselle van Dongen（嘉宾）：在 Restate 中，我们可以使用一种叫作虚拟对象的东西来建模。以我演示的 Slack 研究智能体为例，假设我不想等十分钟才给它补充上下文，或者突然想到还有些信息应该告诉它。

Giselle van Dongen（嘉宾）：我希望能够直接与它交互，而不是等研究结束后才能发送后续消息。这基本就是 Restate 中虚拟对象的作用。

Giselle van Dongen（嘉宾）：它有点像一个有状态的 Actor，拥有唯一 ID，比如会话 ID。它还有一组专属于该会话、彼此隔离的键值状态，可以写入数据，比如消息历史记录。此外，它还拥有一组处理器，可以为该会话执行持久化函数。

Giselle van Dongen（嘉宾）：对于刚才提到的、与运行中进程交互的场景，我是这样实现的。这是一个会话控制器。同样，它可以使用 Restate 对象上下文，以可恢复的方式执行操作。它可以写入会话存储，这里我正在获取聊天记录。

Giselle van Dongen（嘉宾）：有一点很有意思：为了以高度并行的方式运行这类会话，也就是同时运行数千个会话，我们必须确保智能体之间不会相互干扰。

Giselle van Dongen（嘉宾）：想象一下，我在 Slack 中连续发送两条消息，两个智能体可能会互相覆盖会话状态。为了避免这种情况，系统会保证同一时间只有一个执行在运行。第二个执行会排在当前执行之后等待。

Giselle van Dongen（嘉宾）：接下来看看如何实现这一点，也就是如何与另一个执行交互。Restate 中的执行都有唯一标识符。你可以用这个标识符从其他进程连接到它，例如获取输出、取消执行，或者向正在运行的智能体循环注入一些状态。

Giselle van Dongen（嘉宾）：因此，这是一种非常灵活的能力，可用于向正在进行的智能体循环发送信号。

## 06 动态注入、取消与回滚

Giselle van Dongen（嘉宾）：具体来说，如果当前有正在进行的执行，我们会询问大语言模型：“这条信息是否与当前智能体循环相关？”如果相关，就通过信号将它注入。

Giselle van Dongen（嘉宾）：如果与当前任务无关，就取消当前执行，并用这条新信息重新开始。这就比普通工作流更进一步，更接近于编写能够彼此交互、拥有记忆的持久化有状态实体。

Giselle van Dongen（嘉宾）：下面演示一下它是如何工作的。现在我再次询问“AI 最近有什么新动态”，等待几秒后，它应该会再次返回一个计划。

Giselle van Dongen（嘉宾）：然后我可以补充一些信息，比如：“重点关注前沿模型。”拿到计划后，我会注入这部分额外状态。

Giselle van Dongen（嘉宾）：现在看看界面上发生了什么。这里就是刚才展示的控制器。它开始调用大语言模型，对这条新输入进行分类。

Giselle van Dongen（嘉宾）：返回结果后，它可能会判断应该发送信号，因为这条信息仍与当前研究相关。于是，这条新消息就被注入正在运行的智能体循环。

Giselle van Dongen（嘉宾）：再回到深度研究智能体。它先调用了大语言模型，然后向我们提问；接着我们注入了“关注前沿模型”这条新消息。之后它考虑了这条信息，并重新开始执行。

Giselle van Dongen（嘉宾）：现在我还可以说：“不要再研究 AI 政策了。”发送后，协调器会取消当前运行，并启动一个新的执行来研究这个新主题。

Giselle van Dongen（嘉宾）：这个取消操作本质上就像一个沿着调用栈或调用链向下发送的信号。因此，如果智能体已经启动了子智能体，系统会先取消子智能体，再取消控制器本身。

Giselle van Dongen（嘉宾）：这样就能回退调用栈，也让智能体具备回滚能力。这部分更偏向于能够在较长时间内与之交互的、有状态持久化实体。

## 07 生产环境中的扩展与定制

Giselle van Dongen（嘉宾）：演示的最后一部分，是如何编写高度定制化的应用。

Giselle van Dongen（嘉宾）：假设我们把它部署到生产环境，几个月后，某个新的模型供应商推出了一个新模型。这个模型虽然效果很好，也非常昂贵。我们发现，这个研究智能体的成本开始变得很高。

Giselle van Dongen（嘉宾）：项目进行到一半时出现的这类问题，往往要求你部署大量新基础设施，或者找到合适的解决方案。这正是 Restate 擅长处理的事情。

Giselle van Dongen（嘉宾）：它不会把你限制在某一种应用编写方式上。它提供的是一种持久化编程模型，让你按适合自己的方式实现应用，并在需要时进行扩展。

Giselle van Dongen（嘉宾）：刚才第一个例子中，我把大语言模型调用作为一个内联步骤。它只是一个被持久化的 Python 函数。

Giselle van Dongen（嘉宾）：但假设我们希望对这些大语言模型调用拥有更多控制，比如可以把它提取为独立的处理器。这个处理器现在可以先进行策略检查，再调用大语言模型。

Giselle van Dongen（嘉宾）：其他智能体不再内联调用大语言模型，而是使用 Restate 提供的分布式通信原语，调用这个大语言模型网关。

Giselle van Dongen（嘉宾）：这个用于智能体间通信的服务层还提供流量控制等能力。例如，我们可以规定某个部门同时最多只能向这个大语言模型网关发起 300 次调用。我展示这个例子，是想说明这一点。

Giselle van Dongen（嘉宾）：它本质上就是一个具备韧性的基础，确保你的进程即使遇到更复杂的基础设施故障，也能恢复，比如网络分区和僵尸故障。同时，它还提供工具，让你随着应用场景扩展而继续定制和扩展。

## 08 架构、部署与结语

Giselle van Dongen（嘉宾）：回到幻灯片，进一步了解它内部是如何实现的，因为它的设计和架构确实很有意思。

Giselle van Dongen（嘉宾）：它的实现基础是事件驱动的分布式日志。在这个框中，一侧是客户端，另一侧是服务。框内是一个日志，用于持久化所有事件日志，以及一个事件循环。

Giselle van Dongen（嘉宾）：事件循环会从服务接收事件，然后根据事件类型，将状态持久化到嵌入式状态存储中、设置定时器，或向另一个智能体发送请求。这样，你就为应用执行的各种操作提供了一个持久化基础。

Giselle van Dongen（嘉宾）：这个分布式日志的设计深受 Meta 核心事件基础设施工作方式的启发。可以说，这是在其基础上的一次迭代。其中一些架构师后来为 Restate 设计了更通用的解决方案，并将其作为开源项目提供。

Giselle van Dongen（嘉宾）：这个架构有两点很重要，也很有意思。第一，它采用推送模型。大多数工作流编排器会从工作流服务器拉取新任务，而 Restate 会主动推送调用请求。这样做的好处是延迟低得多。

Giselle van Dongen（嘉宾）：因此，你可以在应用周围的函数中使用这类工作流保证。例如，一个包含十个步骤的工作流，P99 延迟可以达到 45 毫秒。

Giselle van Dongen（嘉宾）：推送调用也非常适合无服务器环境，因为它只需发送请求并唤醒函数。我展示的这个设计包含了你所需的一切。它还包含状态存储，用于嵌入状态。它是一个单一二进制文件，因此也很容易运维。
