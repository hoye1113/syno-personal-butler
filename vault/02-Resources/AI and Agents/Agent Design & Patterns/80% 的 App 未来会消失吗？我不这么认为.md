# 80% 的 App 未来会消失吗？我不这么认为

> 三元同学对 Peter Steinberger（OpenClaw 创始人）"80% App 都会消失"观点的反驳：承认一部分 App 会被替代，但产品价值在品味和封装，不在功能。

## 引子

最近到处都在传一个观点：80% 的 App 未来都会消失。这话最早是最近大火的 OpenClaw 创始人 Peter Steinberger 在播客里说的。

他的逻辑其实挺清晰的——当你有一个 AI Agent，它可以通过各种技能包（Skills）接入邮件、浏览器、智能家居、地图 API 等等各种能力，那你很多时候不需要打开一个单独的 App，直接跟 Agent 说一句话就行了。

他举了个例子：不需要 MyFitnessPal（一款健康 App），拍张食物照片 Agent 就能算热量、调整健身计划。甚至连闹钟 App 都不需要，Agent 能直接连接到你的 MacBook 把音量开满叫你起床。

他的判断是：大部分 App 最终会被简化成 API，Agent 直接调 API，App 的那层"壳"就不需要了。

这话本身是有道理的。但如果就此推导出"大部分 App 都不需要了"，那就是把一个局部现象当成了全局趋势。

## 先说他对的部分

有一类 App 是真的会被替代的：

- **纯数据查询和转换的**——汇率计算器、天气查询、单位换算。这些本质上就是 API 套了个壳，Agent 能直接调，确实不需要单独装个 App
- **简单的内部 CRUD 工具**——Peter 在播客里提到一个设计公司的人，不会写代码，用 Agent 搭了 25 个内部 Web 服务。这种场景 Agent 确实够用
- **个人自用的小工具**——vibe coding 撸一个出来也没问题

这些都认同。

## 产品不只是功能

这是很多人没想明白的一件事。你用一个习惯养成 App，真的是因为它的功能吗？如果只是功能，苹果自带的提醒事项就能解决。你之所以用它，是因为它的 UI 风格让你觉得舒服，它的交互节奏让你觉得愉悦，它的产品理念你认同。

这些东西加在一起，构成了一种**品味（taste）**。

品味不是某一个功能，它是产品团队在千百个细节上做出的隐性决策的总和——按钮的圆角半径、动画的缓动曲线、文案的语气、留白的比例。这些东西你写不进 prompt 里，因为品味本身就不是一个可以被显式描述的东西。

你让 AI 撸一个习惯养成 App，它可以做到"能用"。但"能用"和"想用"之间，差的就是这层品味。而这层品味，恰恰是很多人愿意付费的理由。

这不是功能层面的竞争，这是**工艺品层面的竞争**。就跟你不会因为能在家里自己泡咖啡，就觉得所有咖啡馆都该关门一样。

## 产品是复杂度的封装

再说另一个维度。假如我现在要做一个个人助手问答网站。我的第一反应是什么？大概率是去 Coze 或者 Dify 这种平台，用平台能力搭一个 Chat 页面出来。

你说用 AI 从头写一个行不行？从我一个搞技术的视角来看，当然可行。但你想想，这个过程我需要处理哪些东西——前端页面、后端接口、流式输出、对话历史存储、鉴权、部署、域名、HTTPS 证书……

这还只是上线。上线之后呢？服务器宕了谁来修？依赖库出了安全漏洞谁来升级？

产品的价值不只是帮你把代码写出来。它封装的是从开发、到运维、到迭代、到安全的**整条链路的复杂度**。你用 Coze 搭一个 Chat 页面，本质上是在为"我不想操心这些杂事"买单。

这个逻辑在企业场景更明显。你的银行 App、你的医疗健康 App、你的财务系统——这些东西你敢用自己 vibe coding 出来的版本吗？合规审计、数据安全，这些不是写几行代码就能搞定的，是产品公司用大量成本解决的问题。

**所以，产品的一大本质，就是"我帮你操心"。** 它不只是功能的集合，它是一种服务，帮你把那些你不想管、管不好、管不过来的事情兜住了。

## 真正在变的是什么

coding 的门槛确实在降低，AI 确实能帮你做很多以前做不了的事。但由此推导出"App 会消失"，这个因果关系是有问题的。

门槛降低，意味着更多人可以做产品了。以前你有个好想法但不会写代码，产品做不出来。现在 AI 帮你搞定了技术实现，那挡在你和一个好产品之间的障碍是什么？

是你对用户的理解。是你的审美。是你愿不愿意在细节上死磕。是你能不能在一千个"差不多就行了"的时刻选择"再打磨一下"。

> **门槛降低不意味着产品的价值消失，它意味着竞争的维度变了。** 以前拼的是谁能把东西做出来。以后拼的是谁能把东西做得好、做得有品味、做得让人离不开。

## 画一条线

与其笼统地说"App 会不会消失"，不如具体点，看看哪些会受冲击、哪些不会：

### 容易被 Agent 替代的

- 纯数据查询和转换（天气、汇率、翻译）
- API 套壳产品
- 简单的个人自用小工具
- 纯信息输入和输出的内部工具

### 不太容易被替代的

- 有设计品味和情绪价值的产品
- 需要长期维护、安全合规的复杂系统
- 封装了大量运维和服务能力的平台型产品
- 有社区和网络效应的产品

会发现，Peter 在播客里替代掉的那些东西——MyFitnessPal、闹钟、餐厅查询——恰好都是前一类。但他自己也没替代掉 WhatsApp、没替代掉 Spotify、也没替代掉他用来跑 Agent 的那台 Mac 上的操作系统。

## 最后

coding 的门槛降下来了，这是好事。但如果你因此觉得"产品没价值了"，那你可能从一开始就没搞明白产品的价值到底在哪。

产品的价值从来不是"帮你写了段代码"。它是品味，是封装，是"我帮你操心"。这些东西不会因为 AI 能写代码就消失，反而会因为代码变得廉价而更加稀缺。

当所有人都能做出一个"能用"的东西时，让用户觉得"好用"和"想用"才是真正的战场。
