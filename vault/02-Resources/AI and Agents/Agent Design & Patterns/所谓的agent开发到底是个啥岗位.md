# 所谓的agent开发到底是个啥岗位

> 如果你希望长期端稳"开发"这碗饭，这篇文章适合你。

直接讨论当下"Agent 开发岗"的工作职责其实没意义，因为 AI 发展实在太快，任何岗位需求落到 JD 上都已经过时了。

举例：RAG 需求最大的时候是 GPT3.5 那个时代，但不影响它成为当下 Agent 开发岗要求精通的技能。

所以，面向「未来趋势」做职业规划（而不是面向招聘 JD），是端稳这碗饭的前提。那趋势是什么呢？

## 趋势：生产力决定生产关系

马克思政治经济学提到——生产力决定生产关系，AI 提高生产力，从趋势看势必改变生产关系。当下很多公司出现的现象，比如：

- 设计抢前端开发的活儿
- 产品抢开发的活儿

都是生产关系的变化。

那这种趋势会带来什么影响？答案是：协作方式的变化。具体来说会经历 2 个阶段。

## 协作方式的两阶段演化

### 1. 人机协作的敏捷小组（当下）

AI 提效带来人员冗余，公司在现有组织架构基础上缩减人员，表现为：裁员。当前很多开发想转 Agent 开发岗，就是在这个阶段寻求自救。

### 2. AI 原生的小型蜂群组织（未来）

蜂群的意思：**去中心化 + 高度自治**的小团队。大量承上启下的中层领导岗位被移除，领导层直接对接执行业务的蜂群。

关系变得简单：公司提供数据接口、合规审计、销售渠道和品牌背书等，蜂群拥有高度自主权，根据市场反馈快速迭代。

这时候的 Agent 开发岗（蜂群内的最小节点）要求的是"**业务 + 技术 + AI 协作**"综合能力。

> 这一判断在 FDE（Forward Deployed Engineer）的实践中已有 3 年落地验证——蜂群内的最小节点往往就是 FDE：要能钻进客户业务、能把成果设计出来、剩下的交给 AI 工具链。参见 [[硅谷今年最火的岗位 FDE，我们闷头干了三年]]。

## 所以，要端稳 Agent 开发这碗饭

长远看，与其卷"Coding Agent 该如何调优"这样的细节，不如将精力花在其他业务能力上（比如产品、AI 协作、Marketing...）。

## 反驳：招聘 JD 为啥看着都"传统"？

有人会反驳：我看招聘网站上招"业务+技术+AI 协作"的岗位很少，大部分 Agent 开发岗要求的还是"精通 RAG 之流"。

解释下：

1. 诚如本文开头所说，因为 AI 发展实在太快，任何岗位需求落到 JD 上都已经过时了
2. 大部分公司正在经历**阶段 1**（人机协作的敏捷小组）

归根结底，趋势还没到人人能看清的时候，大部分公司不知道该招什么样的人，也就不知道招聘 JD 该怎么写，就只能抄其他公司现成的 JD，导致市面上 JD 看起来都差不多，进而让更多公司与招聘者坚信"Agent 开发岗就该会这些"。

## 总结

Agent 开发这碗饭要想做长远，需要的是"**业务 + 技术 + AI 协作**"综合能力，不要被当下 JD 上的要求忽悠了。
