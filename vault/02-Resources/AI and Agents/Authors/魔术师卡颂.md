## 魔术师卡颂的核心方法论

### 1. 生产力决定生产关系

Agent 提升生产力 → 生产关系（组织结构）必须跟着变。两阶段：
- **当前**：人机协作敏捷小组（裁员 + AI 叠加在现有结构上）
- **未来**：AI 原生蜂群组织（去中心化 + 高自治 + 中层消失）

出自 [[所谓的agent开发到底是个啥岗位]]。

### 2. 蜂群最小节点 = "业务 + 技术 + AI 协作"综合能力

蜂群内最小节点不是纯 Coder，而是能深入客户业务、设计方案、让 AI 工具链执行的复合型人才——即 Anthropic 的 FDE（Forward Deployed Engineer）。

### 3. 遇事留痕

> "不要把 Agent 跑过的执行过程当作一次性消耗品，而要把它当作项目自我进化的燃料。"

三层留痕：Session Log（基础）→ GitHub Issue/PR（项目记忆）→ 定时任务自动分析日志（Loop Engineering 的基础）。

出自 [[遇事留痕 - Loop Engineering 的基础 - 魔术师卡颂]]。

### 4. 可控实验

> "把不确定问题转化为可控实验。"

两步：模糊目标 → 客观标准（如可复现的 failing test）；执行过程 → 反馈闭环（跑测试 → 假设 → 修复 → 再测）。复杂场景可递归——连写复现测试都难时，先把「写出复现测试」本身当实验。

出自 [[驾驭 AI - 把不确定问题转化为可控实验 - 魔术师卡颂]]。

### 5. AI Native CLI

> "把面向人类开发者设计的 CLI 改造为面向 Agent 设计的 CLI。"

四层：stdout 结构化协议；错误带 `hint` 可恢复；读/写/高危分级权限（`--dry-run` / `--yes` / 人类接管）；大流程内置 Skill 替代文档。实例 [docs-harness](https://github.com/BetaSu/docs-harness)。

出自 [[想锻炼 AI 能力 - AI Native CLI - 魔术师卡颂]]。

### 6. 50% 工作法

> "50% 精力放在业务代码，50% 精力放在 Harness 环境优化上。"

Agent 老问人 → 减并行，修环境 / 业务知识 / 方向三类 Harness 根因；自治变长后再加并行。另一半时间禁止纯摸鱼——否则既不会手写也不会指挥 Agent。AI 知识 3～6 个月半衰期，1 个月学会可吃 2～5 个月效率红利。

出自 [[AI Coding 时间管理 - 50% 工作法 - 魔术师卡颂]]。

### 7. 减框架，增基建

> "减框架，增基建。"

入门用 superpowers（工序）或 gstack（工种最佳实践）；痛点是流程太重、头脑风暴太费时间。定制：文档沉淀 + 提问前先检索；测试金字塔 / lint / OpenAPI 等基建到位后，逐步砍掉 TDD 门控、review、plan，终态 = 重基建 + 轻编排（原生 Plan Mode）。

出自 [[如何为项目定制 Harness 环境 - 魔术师卡颂]]。

### 8. Harness 三层架构

> "Harness = Agent 运行的完整环境。"

底：环境约束（lint、测试金字塔、契约、监控）；中：路由（Skill Description、AGENTS.md），宜薄、渐进披露；顶：流程编排（superpowers 过程 / gstack 角色），宜按需裁剪。框架在顶，Harness 是整环境。

出自 [[AI框架与 Harness 的关系 - 魔术师卡颂]]。

### 9. Skill 自动优化循环

> "定时任务收集反馈 → 反馈归因到规则 → 优化 Skill 的规则集。"

PR Review 场景：每周拉 review JSON → 找 bot 误判/建议不可落地等模式 → 只改「诊断规则」子集 → 提 PR 人工审。须：改规则不改全流程、正负反馈明确、可归因。参考 warpdotdev/common-skills。

出自 [[如何让 Skill 自动优化 - 魔术师卡颂]]。

### 10. Loop 套 Loop

> "未来的 AI 编程就是 Loop 套 Loop。"

一层：需求 Loop，门禁验收（lint/测试/CI/Agent PR Review）。二层：扫描 Session Log → 模式偏差 → 新增 gate 的 issue。三层：issue 处理与评论作反馈 → 改进「发现偏差」的规则。人关注的信息逐层压缩。

出自 [[未来的 AI 编程就是 Loop 套 Loop - 魔术师卡颂]]。
