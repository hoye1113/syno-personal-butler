# Garry Tan：“个人 AGI 是保持自主力量的方式”

> 这篇专栏整理 Garry Tan 关于个人 AGI、上下文基础设施、Skills、认知所有权和个人行动的分享。
>
> **核心主张：** 个人 AGI 的关键不只是一个更强模型，而是把个人知识、判断、记忆和行动规范沉淀为自己能够控制的基础设施。

> 个人 AGI 是保持自主力量的方式。
> ——Garry Tan（专栏整理）

## 开场

专栏把个人 AGI 描述为一种长期的个人基础设施，并讨论知识库、技能文件、Agent 组织与所有权。下文按行动逻辑重构问题与回答；案例数字和个人经历只按专栏口径记录。

## 01 个人 AGI 不等于等待一个超级模型

**核心判断：** 个人 AGI 更像一个围绕个人目标运行的基础设施，而不是某天突然从云端降临的单一产品。

**编者问：** 为什么要现在建设个人 AGI，而不是等模型能力成熟？

**Garry Tan（专栏整理）：** 模型能力会变化，但个人的目标、经历、偏好和决策历史会持续积累。现在建立可迁移的知识、技能和反馈机制，可以让未来模型更容易理解个人，也让个人不被某一家模型服务锁定。个人 AGI 的“个人”首先指控制权和上下文归属，而不只是一个私人聊天窗口。

## 02 上下文是个人基础设施的核心资产

**核心判断：** 对个人 Agent 来说，能否找到并正确使用相关上下文，往往比单纯增加模型参数更直接地影响行动质量。

**编者问：** 大量 Markdown 知识如何真正帮助个人工作？

**Garry Tan（专栏整理）：** 个人知识库可以保存会议、项目、决策、关系和经验，但价值不在文件数量，而在于系统知道什么时候检索、如何判断来源和怎样把知识转成下一步行动。专栏以数十万页 Markdown 的个人资料规模作例子；这属于作者口径，不能直接作为所有人的推荐规模。小而可靠的上下文，通常比不可维护的资料堆更有用。

## 03 Skills 把判断从脑中外化

**核心判断：** Skill 不只是让 Agent 会做某件事，更重要的是把“什么情况下做、做到什么标准、如何检查”显式化。

**编者问：** 为什么技能文件会被称为认知资产？

**Garry Tan（专栏整理）：** 一次会议结束后，Skill 可以要求系统提取决策、责任人、承诺和下一次检查；一次复盘后，Skill 可以把判断标准写回流程。这样个人的经验不再只能靠记忆传递，也可以被反复执行、修正和审计。外化并不意味着把判断交给模型，而是让人更容易看见、修改和收回判断。

## 04 模型判断与确定性代码要分工

**核心判断：** 语言模型适合处理模糊理解和方案生成，确定性代码适合执行规则、计算、权限和不可含糊的状态转换。

**编者问：** 如何避免个人 AGI 变成一个“什么都让模型猜”的黑箱？

**Garry Tan（专栏整理）：** 可以让模型解释邮件、会议和需求，再把关键条件交给确定性工具校验。例如日期、金额、权限、提交状态和提醒条件应有明确规则，模型负责的是从自然语言中提取候选信息。把两者分开，既能保留模型的灵活性，也能让个人知道哪些结果可以自动执行、哪些必须复核。

## 05 认知所有权是组织问题

**核心判断：** 当个人经验被转成公司内部 Agent 后，知识归属、迁移能力和个人控制权会成为真实的组织与政治问题。

**编者问：** 为什么个人 AGI 的讨论最终会涉及所有权？

**Garry Tan（专栏整理）：** 如果个人的工作方法只存在于某个公司的私有系统中，离开组织时可能无法带走自己的判断和历史。个人可以保留可导出的知识、技能和决策记录，公司则需要明确哪些是组织资产、哪些是个人经验，以及如何在隐私和协作之间划边界。自主不等于拒绝组织，而是让边界和迁移权可被讨论。

## 06 从一个可复用闭环开始

**核心判断：** 建设个人 AGI 最实际的起点是选一个高频任务，记录输入、判断、动作和结果，再把稳定部分沉淀成 Skill。

**编者问：** 个人今天可以采取哪些第一步？

**Garry Tan（专栏整理）：** 先集中保存可靠笔记，建立简单的命名和来源规则；再为会议、收件箱或项目复盘写一个小 Skill，明确输出和人工检查点。让 Agent 先做检索、摘要和候选行动，成功后再扩大权限。每次失败都应该更新上下文或流程，而不是只更换模型。持续的小闭环，比一次性搭建宏大的“个人操作系统”更容易保持控制。
