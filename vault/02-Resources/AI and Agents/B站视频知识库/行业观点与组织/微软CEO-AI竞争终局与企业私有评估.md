# 微软CEO：AI竞争终局与企业私有评估

## 开场

微软 Build 2026 刚结束，纳德拉在台上连发三小时。Sarah Guo 把他拉到《无先验》和《潜在空间》的交叉集里，问的不是「哪个模型最强」，而是 **AI 竞争的终局长什么样**。

纳德拉的答法很直：别把它想成单一模型、甚至单一平台的战争，要当成 **生态系统玩法**。他在微软经历过四次平台转型——平台好不好，看它在平台之外创造了多少价值，不是看能把多少价值锁在自己围墙里。

这场对谈六条线：**生态 vs 单模型** → **干净血统与私有评估** → **部署难与线束** → **画布 UI 与长期代理** → **SaaS 解绑与 Work IQ** → **元工作、数据中心与社会许可**。贯穿始终的一个判断：企业护城河从代码转向 **私有评估 + 代理轨迹**；换模型还能继续爬坡，才算真有自主权。

**术语速查（后文对话用中文；英文原文在此统一对照解读）**

| 中文 | 英文 | 白话 |
|------|------|------|
| 爬坡支架 | scaffolding | 在通用预训练模型外，用 RL、轨迹、评估把模型磨成领域专家的那套支撑 |
| 干净血统 | clean lineage | 预训练数据与流程可追溯、少污染，小模型也能可靠爬坡 |
| 私有评估 | private evaluation | 只有你自己有的任务评测集，公开榜单刷满分也不顶用 |
| 线束 | harness | 把模型、数据、工具串成闭环，代理才能稳定干活 |
| 画布 | canvas | 像 IDE 一样管很多长期代理会话的工作界面，不单一个聊天框 |
| 工作智商层 | Work IQ | 微软把 M365 里的邮件、文档、会议暴露成代理可调用的数据层 |
| 元工作 | meta-work | 人不亲手修光纤，而是运营「替自己修光纤的代理系统」 |
| 缩放定律 | scaling laws | 算力上去，智能大致按对数涨——粗说法仍成立 |

## 01 平台价值在生态，不在单模型

**Sarah Guo：** 你今早连讲了三小时发布。如果只能留一个收获，是什么？

**Satya Nadella：** 我会把它想成 **生态系统**，不是单一模型，甚至不是单一平台。

我在微软长大，亲眼见过四次大平台转型。我属于那种人：平台靠 **根本能力** 定义——它在平台 **之外** 创造了多少价值，而不是围墙里锁了多少价值。

你看现在正在发生的事：今早主题演讲其实在回答——不管 AI 原生公司还是传统企业，怎么当 **一流玩家** 参与进来。你可以展示自己的 AI，也用别人的 AI，这不打架。难的是路径：堆栈长什么样？工具是什么？什么才值钱？怎么落地？这是我们的活。

**Sarah Guo：** 生态战略很复杂啊。有些组件自己做，有些找伙伴，还要扶持别人。你们刚发了一串大模型——微软的训练策略到底是什么？

**swyx：** 我们想用 MAI 模型干什么？穆斯塔法说过，从预训练抓起，数据质量要好，消融做透，模型才站得住。

**Satya Nadella：** 说实话，现在外面干扰太多，要造 **干净血统** 的模型反而更难——你得把噪音剔掉，才拿得到像样的预训练。很多开放模型在一个两个榜单上很漂亮，真用起来却拉胯。

所以我们对 Phi、对 MAI 都很兴奋。一个 3B、5B 的小模型，凭什么能爬坡？归根到底，是找到那个 **认知核心**。从干净血统出发，给公司机会：不只是当通才，而是围着模型搭 **爬坡支架**，养成自己的专家。

然后你开始上强化学习，开始收 **轨迹**。最要紧的是 **私有评估**。公开评测集有意思，现阶段却没那么关键——大家都能刷到顶。每个公司都会有自己的私有评估。围绕我们模型的端到端平台故事，我觉得这才好玩。

还有一层「前沿」值得单独说。大家老问你在不在前沿。你要是加上 **时间维度**，玩法又不一样。我们给 Land O' Lakes 做的演示就很酷：先用 GPT-4o，收一堆轨迹，再换 5B 推理模型，成绩反而更高。这也是一种在前沿上往前走。

> **金句 · Satya Nadella**
> **中文：** 平台好不好，看它在外面创造了多少价值，不是看它能锁住多少。
> **原文：** A platform is defined by how much value it creates outside the platform, not just what it captures inside.

**本章概念**

| 中文 | 英文 | 白话 |
|------|------|------|
| 爬坡支架 | scaffolding | RL + 轨迹 + 评估，把通才磨成垂直专家 |
| 干净血统 | clean lineage | 预训练可追溯、低污染，小模型也能实用爬坡 |
| 私有评估 | private evaluation | 企业专属任务集，公开榜满分≠你真能交付 |
| 轨迹 | trajectories | 代理干活留下的步骤记录，用来继续训练与评测 |
| 认知核心 | cognitive core | 小模型仍能变强的能力内核，不靠无脑堆参数 |

**本章小结**

- 竞争单元是生态，不是「谁家参数最多」
- 训练策略强调干净血统 + 支架，让小模型也能领域爬坡
- 公开评测饱和后，私有评估才是各公司的真赛场

## 02 智能是对数的算力，部署却被全行业低估

**Sarah Guo：** 先祝贺你——两年内在微软里基本从零拉起一个前沿实验室，AI 战略一股脑推出来。要是能穿越回两三年前，你会对自己说什么？

**Satya Nadella：** 我入坑，是被 **缩放定律** 那篇论文勾住的。OpenAI 合作机会来时，他们说要把海量算力砸在 Transformer 上，他们也真砸了。

我老回头看：这些东西确实一路往上走。那句粗话——**智能大致是计算的对数**——还站得住。

我们可能低估了 **在现实世界部署** 有多难，以及怎么让模型在真实场景里值钱。榜单分数有意思也重要，可真正的评估是：人们能不能完成 **他们自己觉得有价值** 的那件独特的事。这能量化。我但愿我们更早看清这一点。

作为一个行业，现在大家会说：我不想光 **烧代币**。这是我们以前没深想透的产物——每一步都要用代币 **创造价值**。这就是我想带我们去的方向，好在现在已经站到这个门口了。

> **金句 · Satya Nadella**
> **中文：** 真评估不是刷榜，是用户能不能做成那件只有他在乎的事。
> **原文：** The real evaluation is whether people can do the unique things they find valuable—not benchmark scores.

**本章概念**

| 中文 | 英文 | 白话 |
|------|------|------|
| 缩放定律 | scaling laws | 算力增，能力涨，但边际是对数式的，不是线性白送 |
| 代币效率 | token efficiency | 每花一枚代币要换回可感知的业务价值 |
| 部署复杂性 | deployment complexity | 从实验室分数到产线可靠交付之间的鸿沟 |
| 价值创造 | value creation | 用户独特任务完成度，比榜单排名更贴地 |

**本章小结**

- 缩放定律仍成立，但「能跑分」≠「能交付」
- 行业新焦点：代币要花出价值，不是单纯消耗
- 与 [[OpenAI评估团队-不再低估模型]] 同向——评测要贴真实工作，不是 bench gaming

## 03 代理世界需要画布，聊天框扛不住

**Elad Gil：** 哪些用例给客户创造了最大价值？大家老聊代码，还有呢？

**Satya Nadella：** 编码确实已经很大了。有意思的是，编码好到 **我们得重做 IDE**。我们发的东西简直疯狂——我同时开着 **上百个代理会话**，传回来的 **认知负荷** 大到我必须换界面。光靠聊天当唯一交互，不现实。所以要 **画布**。

软件该放哪、UI 该长什么样，在 **完全代理化** 的世界里，连写代码都要重新想。我们在协同、在自动驾驶条款那类场景里看到趋势：很多人力在做 **连接工作**。你用长期运行、能持久的代币代理去增强它，扩展判断和连接的能力，会像编码一样被放大。

我敢打赌，半年后我们会说：一整夜好多事发生了，一堆自动驾驶仪在我授权下干活。我可以问新来的 ADE：你昨晚干了啥？我交代的事完成了吗？这就是 **工作流被压缩、任务被做完** 的地方，价值在这冒出来。

**Elad Gil：** 写代码的代理外面套着一层 **线束**——环境、上下文、你作为开发者围上去的一切。企业做广义生产力，等价的线束是什么？

**Satya Nadella：** 线束要定义 **模型、数据、工具**，让三者形成循环。所以我们做的每个产品——GitHub Copilot、安全 Copilot、M Dash、科学发现——都一样：带工具访问的 **多模态线束**。你可以逐步公开工具，甚至让代币更省。

然后用 **很厚的上下文** 喂它。过去两年我们学到的硬课：得在上下文层下大功夫，计划才能最有效执行。我们有 GitHub 线束，基本上所有产品都在用；在 Foundry 里开放，你可以用 Llama 线束、开放线束或自建线束，配上你的工具、多模型和上下文来训。

卖点在这：很多人争论，把线束、工具和模型一起训，就能得到评估。我们用 M Dash 证明了——上线时抓到 Mythos 没抓到的漏洞。**多模态线束在现实世界里可以更强**，这不是口号，有案例。

> **金句 · Satya Nadella**
> **中文：** 上百个代理同时跑，聊天框不够用了，你得要一块画布。
> **原文：** I have a hundred agent sessions—the cognitive load is so high I need a new UI; chat alone is impossible, that's why we need a canvas.

**本章概念**

| 中文 | 英文 | 白话 |
|------|------|------|
| 线束 | harness | 模型+数据+工具+上下文的执行闭环 |
| 画布 | canvas | 管理多会话、长期代理的 IDE 式界面 |
| 多模态线束 | multimodal harness | 不只会写字，还能看图、调工具、走工作流 |
| 连接工作 | connection work | 条款对齐、跨人协调——代理增强的高杠杆区 |
| 代币代理 | token agents | 长期运行、可授权的自动化劳动力 |

**本章小结**

- 编码代理规模化后，UI 必须从聊天升级到画布
- 企业级价值在「线束」：模型、数据、工具循环 + 厚上下文
- 与 [[2026 年 Agent 最重要的工程概念 Harness Engineering]]、[[IBM团队-Harness工程详解]] 同框架——纳德拉从平台 CEO 视角把 harness 说成竞争单元

## 04 私有评估是最大知识产权，能换模型才算自主

**swyx：** 独立实验室训练模型的前提是 API 和模型生意。可第一方产品——生产力、代码、搜索——占收入大头。跟你说的生态价值等式不太一样吧？开发者在这世界里怎么活？

**Satya Nadella：** 平台造得很成功，同时做第一方产品——Windows 时代如此，SaaS 和云时代也如此。关键是 **别挡住别人同样成功**。

这次差别在于，围绕智能的 **网络效应** 特别大：模型能从数据里学，而且不用海量数据，几个样本就能抓住新意。竞争就变成 **怎么保护这些**。我认为，每家公司手里的 **私有评估**，可能是最大的知识产权。

这么想：什么是你能拿来在 **前沿模型上继续爬坡**、又 **不泄露轨迹** 的私有评估？这可能是 IP 最大的发动机之一。另一个试金石：你有私有评估，用着模型 A，能切到模型 B 还继续提升吗？能，你就掌控着；不能，你就被绑死。线束选型因此变得要命——开放的线束、各模型都能接、自己的评估和上下文和工具帮你爬坡——这是 AI 原生创业、SaaS、每个企业都该练的技能。

**Sarah Guo：** 微软先是操作系统公司，再是云公司。第三幕会不会是 **线束公司** 或 **评估公司**——怎么组合都行。让每家公司都拥有前沿智能，是你们的使命吧？

**Satya Nadella：** 这就是跟我们一起建平台的承诺：**你的数据，你的智能**。

要是给这届开发者大会写一句标语，我会写：**每个人都能用自己的前沿智能，在前沿上运作吗？** 这太重要了。不然怎么谈稳定均衡？我怎么能说我的公司有终极价值？因为我学会在一个不断变好的平台上 **持续复合**。

Windows 出来时，Adobe 做软件，Autodesk 也是。Jensen 说过，我们做了 DX，他在上面建了 CUDA。我常跟 Jensen 开玩笑：我当年吃亏了，早该认清。你可以铺一层平台，让别人往上建自己的智能层——这才是开发者大会的意义。要是只想让大家崇拜一个模型，那不必办开发者大会。

**Sarah Guo：** 我们后台聊过：公司里的价值以前是人类经验的时长，现在变成 **评估**，以及把代理用在公司里的经验。展开讲讲？

**Satya Nadella：** 归根到底，每家公司仍有人力资本，这依然值钱——人随时能发现差距，这是我们创造价值的方式。我信：这是表达新形式的人类能动和抱负，哪怕代币资本在涨。假设一家公司有大量代币、大量人力，问题是怎么 **复合**？

团队里一群代理、一群人、它们之间的轨迹——这对企业创造价值是核心上下文。说的不是训一个通用模型，是 **训公司**：资深代理，极值钱。公司说该进资产负债表，我是这么想的。人力资本从来很难入账，因为你抓不住隐性知识；现在我觉得可以靠 **贯穿时间的代理和轨迹** 做到——至少我们会朝这走。

**Sarah Guo：** 美国证监会怕是得给代币专业知识定会计准则了。

> **金句 · Satya Nadella**
> **中文：** 能换底层模型还继续爬坡，你才真自主；换不了，就被绑死了。
> **原文：** If you can switch from model A to model B and keep improving, you're in control; if not, you're not.

**本章概念**

| 中文 | 英文 | 白话 |
|------|------|------|
| 私有评估 | private evaluation | 不对外泄露的爬坡标尺，也是最大的隐性 IP |
| 模型切换试金石 | model switch test | 换模型性能不掉，才算掌握自主权 |
| 训公司 | train the company | 用轨迹和代理沉淀组织知识，不是只训通用大模型 |
| 前沿智能 | frontier intelligence | 每家企业都能在前沿模型上持续复合的能力 |
| 隐性知识 | tacit knowledge | 过去难入账的经验，借代理轨迹有望量化 |

**本章小结**

- 模型趋同后，私有评估 + 轨迹比「谁的代码多」更像护城河
- 开放线束 + 可切换模型 = 企业自主权的技术试金石
- 与 [[OpenAI评估团队-不再低估模型]] 互补：那边讲 frontier eval 方法论，这边讲 eval 作为企业资产与资产负债表

## 05 SaaS 要解绑重绑，Work IQ 把办公数据变成数据库

**swyx：** 均衡状态里，公司有复合价值、看得见终极价值。可还有垂直、水平的通用应用和工作流——SaaS 就是这么长出来的，微软也做了一大堆 SaaS。你也听过「软件终结」吧——工作流生成便宜了。以后企业自建代理和供应商代理，平衡会变吗？

**Satya Nadella：** 过去二十年，我们习惯在应用里 **捕获工作流**：给业务流程建数据模型，上面堆业务逻辑，再堆 UI。SaaS 和配置工具都这套路。

现在可以重新审视这条 **垂直堆栈**。每个 SaaS 下面的 **数据模型** 往往很好——总账就该是总账，不必重造 schema。实体关系是健壮的东西，该养好、保持稳定。业务逻辑也一样：Power BI 仪表盘底下有丰富语义模型，有人费劲做了测量，你希望这些逻辑 **为你所用**。

SaaS 商业模式的挑战是：我们以前那样打包，现在得学会 **解绑**，再 **用新方式重绑**，找新定价。

微软 365 上的 **Work IQ** 是好例子。历史有点像：我们卖 Exchange、SharePoint，Teams 之前有 Link Server。我们以为迁云就完事，没想到云上用户是以前的十倍、百倍——人不买服务器了，买订阅。

M365 也在发生同样的事。Work IQ 把公司里 **最重要的数据库** 暴露出来——以前被应用独占，没当数据库用过：邮件、Teams、Word、Excel、PowerPoint 全在上面。最酷的一例：我去 GitHub 仓库说，上周我参加了很多跟这个仓库相关的设计会，能不能全记下来，告诉我该改哪？它真去翻记录，带着 **改代码库的计划** 回来。以前你不会想用 M365 干这个。代理世界里，创造价值的机会 **大了十倍**——但要有 M365 这种底座，用量甚至可能超过终端用户；架构也得重做，服务收件箱的那套不能直接服务代理，我们正在改。

**Sarah Guo：** 这些领域没有永久商业模式。短期你对 **按结果定价**、**按代币定价**、企业捆绑怎么判断？

**Satya Nadella：** 我们一直有 **按用户定价**。那是给要预算确定性的人发明的——一组使用权限，好算账。第一种捆绑是把一些用量塞进按用户订阅里卖。

下一大趋势是 **按消费**。也有人会说：我连订阅和消费都不想付，要 **按结果付费**。但记住，大多数人喜欢结果，直到 **真拿到结果**——就像付版税。我跟拥抱结果定价的客户聊，我说同意，直到他们反应过来：你要分我的成果？不，还是回到按用户或按消费吧。这场争论会继续，每种模式都有时空，不会一统天下。

做 SaaS 或平台， **灵活** 很重要。GitHub 也刚经历这个：Copilot 最初按用户建，那时我们还不懂代理使用强度。那是开发者跟代码交互的方式，不像现在能一口气起一万个代理跑一整天。**按用户会一直在**，但必须配 **消费计量器**。

**Elad Gil：** SaaS 能撑多久？有些团队对代理狂热，想重建一切，跟供应商说拜拜；六到九个月后又回来，发现自己重建不了全部。什么持久、什么不持久？

**Satya Nadella：** 得走完一整轮 **预算周期**，均衡才会显形。生成式应用也有 **边际成本**。简单说法：你自己建、自己维护的边际成本更高，就该 **买**。这得能量化。维护很关键——AI 会挖出安全问题，你得修，修也花代币。谁担责？这是个循环。

我们刚经历过「能生成海量软件」的兴奋，接下来要问：我 **真想生成什么**？什么该 **用别人的**？怎么合成一条我有自主权的代理工作流？供应商不灵活，用户耐心会很低；灵活、能交付价值的，客户会回来。**我们还在卖软件**，只是商业模式换了。

**Satya Nadella：** （接软件构建）说实话，造软件的门槛低到 **像我这种不太会写的 CEO 都能弄** 了，谢天谢地。GitHub Copilot、新的 Sessions，让我对以前碰都不敢碰的工件有了自主权。CEO 也能进代码库看懂上下游——不等于人人都该写代码，而是 **检查、学习、观察** 的空间大得多。

我在搭很多 **长期运行的 Foundry 代理**。最简单的是「个人幕僚长自动驾驶」：用 Work IQ 起代理，Ray Fin 把内存放 BaaS，然后说「发布到 Teams」——端到端走通，像奇迹。

**Elad Gil：** 工程角色会怎么变？有人猜四五年后只剩四类：管代理的、前线部署工程师、安全、大规模基础设施。其余坍缩进代理世界。你同意吗？

**Satya Nadella：** 得靠实验说话。LinkedIn 最近做了结构性调整，新学科叫 **全栈构建者**——设计、产品、前端的人拉到一起，仍保留专业纵深。不是设计师不会设计了，是 **角色范围** 可以更大。基础设施变得极关键：Excel 团队要建能学奖励的强化学习环境，那是难啃的分布式问题——终端应用团队也要分布式系统人才。

**通才** 的角色会最刺激，杠杆最大。你问我写不写代码？我是通才，在 **翻译知识工作**。以前写 Word、做表，现在能搭应用——同一语境里发生的事。[[LCA-60分钟变成AI-Native]] 讲的 People + Agents + Context，在这里是 CEO 版落地。

> **金句 · Satya Nadella**
> **中文：** 邮件和会议记录一直在那儿，只是以前没人把它们当数据库；代理时代才用得起来。
> **原文：** The most important database in the company was locked inside our apps—email, meetings, documents—Work IQ finally exposes it for agents.

**本章概念**

| 中文 | 英文 | 白话 |
|------|------|------|
| 工作智商层 | Work IQ | M365 数据面暴露给代理，跨应用推理 |
| 解绑重绑 | unbundle / rebundle | SaaS 拆开数据、逻辑、UI，用代理时代新套餐卖 |
| 按结果定价 | outcome-based pricing | 按成果分成，客户真爱直到要分钱那一刻 |
| 全栈构建者 | full-stack builder | 设计+产品+工程范围扩大，仍保留专业尖峰 |
| 长期运行代理 | long-running agents | Foundry 上持久代理，如个人幕僚长自动驾驶 |

**本章小结**

- SaaS 的数据模型和语义层仍值钱，打包方式要变
- Work IQ 示范：办公数据跨 GitHub 设计会 → 改代码计划
- 职业上通才杠杆上升，与 [[所谓的agent开发到底是个啥岗位]]、[[AI 时代如何面试工程师]] 同向

## 06 元工作与社会许可：代币比人头，红利比许诺

**Sarah Guo：** 个人自主权放大到组织：Mike Renal 刚写文章说，这是可以 **更雄心勃勃** 的时代。问管万亿美元公司的 CEO 这事有点怪——微软怎么更雄心？

**Satya Nadella：** 转型里关键是有一个 **概念模型**：工作怎么变，才能做出以前想不到的结果。Kevin Scott 有句话说，当你让不可能发生、让难事变容易，那就是杠杆。真正的雄心是让 **不可能变可能**。

我们组织里缺的是：什么新概念模型？什么不可能，我们能建什么？管 Azure 网络的人去年开始扩展——过去 **十五个月** 建的容量比前 **十五年** 还多，还是同一帮人。他们意识到，不重想工作方式，根本扛不住。

他们建了代理系统：工作不是「做 Azure 网络」，而是 **「构建执行 Azure 网络的代理系统」**。五百多家光纤运营商、广域网，物理活会卡住，得修；本质是邮件进来你要处理。代理叫 Miles，他们开始喊 **要多代币、少人头**——这是对工作性质的 **重新概念化**，把自己活成 **元工作**。八十年代要是有人说四十亿人早上起床开始打字，我会以为要雇四十亿打字员；我们现在做的是知识工作，不是打字。

**Sarah Guo：** 该聊数据中心了。建设规模在重新定义「超大规模」，财务、运营、社区影响都到了新量级。你实地看到了什么？

**Satya Nadella：** 建设规模确实空前，能参与很高兴。另一面：行业必须很有原则，让社区 **真切感受到** 技术好处。不只是运动，得是真的。大家会看：电费涨了吗？长远该降——更好的电网、更多能源。用水：我们在补循环水，得投资培训、就业、税基。建设期和之后创造的就业、对社区税基的贡献，谈得最少，却都该是实的。做到了，才有 **社会许可**；做不到，就没有。行业得认真挣信任。

社区怀疑、问尖锐问题，是好事。我们得干活证明。历史上，大量耗能同时给社会创造巨大价值，故事就好看；只耗能、不产出，故事就难听。我坚信：如果代币经济能推生产力、增长、广泛参与、更好健康结果，我们会站在好位置——这是所有人都该盯的。

**Elad Gil：** 你对 AI 社会影响的认知，最近什么更新最大？什么让你最乐观？

**Satya Nadella：** 我们一开始就问：怎么把故事讲得 **可信**，让每个人都有机会当一流玩家进新经济。接下来十二到十八个月，要让人能说：哦，我明白了。

健康结果、创业能力、本地小店更高效经营——这些正在发生，我自己也看见。**社会许可不能等**。我学到的是：世界会对只说「相信我们，未来很辉煌」的科技业 **高度怀疑**。你得交 **切实利益**。坦白讲，政客会因为倡导这些而 **赢选举**——这次在经济里占比太大，不可能不被这样对待。

**swyx：** 广泛利益除了技术圈，我简单分：财富会在很多公司、初创里创造；医疗在发生，比如 Open Evidence；教育好像还没达到预期，你怎么看？

**Satya Nadella：** 这牵涉我们怎么看待教育。我最近见 Alpha School 创始人，他们重想教育本质，很吸引人——不是说传统教育不重要。斯坦福有些 CS 课很有意思：学生得学怎么 **正确用 Softmax**，不能只会说「帮我修训练」。核心概念仍要学。但激励怎么设、证书是什么、怎么评估、对应什么工作机会，都得 **彻底改**。

获取信息、自学、持续更新的方式都变了，教育模式必须跟。下一个大成功案例，可能是有人办了一所 **新大学** 或新教学法，让人读完就有极有价值的经济机会。很长时间像不可能——现在可能成为现实。

> **金句 · Satya Nadella（封底）**
> **中文：** 别光说未来很美好；社区要看见工作、水电、医疗、教育里的真红利，才会给你许可。
> **原文：** The world will be highly skeptical of tech that only says trust us, the future will be great—you have to deliver tangible benefits.

**本章概念**

| 中文 | 英文 | 白话 |
|------|------|------|
| 元工作 | meta-work | 运营代理系统，而非亲手执行原始任务 |
| 社会许可 | social license | 社区从能源、就业、税基、服务里感受到实益才放行 |
| 代币资本 | token capital | 与人力资本并列，企业复合增长的新要素 |
| 切实利益 | tangible benefits | 医疗、教育、本地经济可验证的改进，非幻灯片承诺 |

**本章小结**

- Azure 网络团队示范：同一班子十五个月建十五年容量，靠 Miles 代理与「要代币不要人头」
- 数据中心必须兑现社区回馈，社会许可是行业生存条件
- 教育与证书体系将因自学与代理重塑，机会评估要跟着改

## 总结：终局是生态、评估与线束，不是单一模型

| 维度 | 要点 |
|------|------|
| 竞争单元 | 生态系统 + 私有评估 + 轨迹，不是单模型参数赛 |
| 工程抓手 | 线束绑模型、数据、工具；画布承载多代理认知负荷 |
| 企业 IP | 能切换模型仍爬坡 = 自主权；评估有望进资产负债表 |
| 产品形态 | SaaS 解绑重绑；Work IQ 把办公数据变成代理数据库 |
| 组织与职业 | 元工作、全栈构建者、通才杠杆；代币与人力复合 |
| 社会条件 | 数据中心与 AI 红利要可感知，许可靠交付不靠许诺 |

### 对企业的启示

- 把 **私有评估** 当核心 IP 建设，与公开榜单脱钩；参考 [[OpenAI评估团队-不再低估模型]] 的 frontier eval 思路，但任务集必须贴你自己业务流程。
- **线束** 保持开放、模型可换，避免被单一供应商锁死；工程细节见 [[IBM团队-Harness工程详解]]、[[MOC - Harness Engineering]]。
- 办公与业务数据层（Work IQ 一类）要能被代理跨应用调用，否则「生成软件很便宜」也换不来端到端价值。

### 对组织与个人的启示

- 岗位向 **全栈构建者**、**管代理的人** 倾斜，与 [[AI 时代如何面试工程师]]、[[所谓的agent开发到底是个啥岗位]] 的蜂群节点判断一致。
- 领导层应允许 **元工作**：团队目标从「亲手运维」转向「运营代理系统」——Azure 网络是内部样板。
- 社会叙事要准备 **可验证红利**（就业、能源、教育、医疗），不是只卖远景。

### 仍待验证

- 「评估与轨迹入资产负债表」仍缺会计准则与 SEC 实践；纳德拉说是方向，不是既成事实。
- SaaS 解绑后各 vendor 定价组合仍在实验期，客户「要结果定价直到真要分钱」的反复会持续多个预算周期。
