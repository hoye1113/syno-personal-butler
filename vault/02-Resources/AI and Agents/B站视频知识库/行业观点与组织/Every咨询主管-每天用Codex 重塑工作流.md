# Every咨询主管-每天用Codex 重塑工作流

> 来源：B 站专栏（Easonlee 的 AI 笔记转述 Dan Shipper 对 Natalia Quintero 的英文对谈）。`source_form: dialogue`，声音依据为专栏直引（`direct_speech`），仅复核专栏本身（`column_only`），未回核原始视频，故 `factual_reviewed: partial`。
>
> **核心主张：知识工作正从「手工雕刻」变成「园艺」——人不再亲手捏产物，而是为 AI 创造共享上下文、画逻辑流程图，在流程首尾把关让系统产生复利；Codex 让非技术者跳过架构焦虑直接表达意图，但确定性软件（成千上万条逻辑规则）该买就买，别用 AI 盲目重写。**

> 传统的知识型工作类似于雕刻，每一个细节都需要你亲手完成；而现在的知识型工作正在变成园艺——你是在为植物的生长创造条件，而不是用手去直接捏出那株植物。
> ——Dan Shipper

## 摘要

Every 咨询主管 Natalia Quintero 认为，AI 员工（如内部智能体 Claudie）已能日常跑通运营，但仍需人类在**品味与方向**上监督，并从数据里提炼关键信号。她的核心判断：知识工作正从"手工雕刻"变成"园艺"——人不再亲手捏产物，而是为 AI **创造共享上下文、画逻辑流程图**，并在流程首尾把关，让系统产生复利。Codex 让非技术者不必关心文件结构/架构即可直接表达意图构建工具；但**确定性软件是成千上万条微小逻辑规则的集合**，已有专业 SaaS（Attio/Asana）该买就买，别用 AI 盲目重写。

## 对话实录

### AI 员工 Claudie 的日常与边界

**核心判断：AI 员工已能日常跑通 SOP，但仍需人类在品味与方向上监督、从数据中提炼关键信号——执行可托管，判断与人际协作不可。**

**Dan Shipper（主持）**：你招了 Claudie 做运营，同时又在招运营专员。内部智能体在什么场景有用、又有什么局限？

**Natalia Quintero（嘉宾）**：Claudie 现在有自己 LinkedIn/Twitter、管仪表盘，还加了"信任电池"系统，循环运行、按反馈自我评估提升，表现很出色。但它极擅长执行 **SOP**，仍需要两样东西：① 持续监督与在**品味/追求卓越**上的方向性指导；② 人际协作维度——仪表盘数据需要有人去挖掘"哪些是关键信号、该引导什么讨论"。所以我们继续扩团队，用 Claudie 呈现的数据做有趣的事。

### 别用 AI 盲目重构已有 SaaS

**核心判断：确定性软件是成千上万条微小逻辑规则的集合，专业 SaaS 的核心业务就是维护它——AI 时代你能构建任何东西，但问题是你真该构建并维护它吗？该买就买。**

**Dan**：你刚从自搭 CRM（Claudie + Google 表格拼凑）迁移到 Attio/Asana。既然能"氛围写代码"生成管理系统，为何还要买？

**Natalia**：我曾氛围写代码拼出 CRM 串联 Slack/会议/表格，但保证数据质量要像管 Claudie 一样时刻盯着，维护成本极高。而 Attio 的核心业务就是这件事。结论是：**AI 时代你能构建任何东西，但问题是你真的该去构建并维护它吗？** 引入专业工具后，管理的信息量更大、团队维护负担反而更轻。

**Dan**：软件和语言模型的比喻——软件像身体的**骨骼**，语言模型像**大脑和韧带**。没骨骼你是滩软水母，没大脑你只是堆木棍；它们协同工作。语言模型也能自己长骨骼，但那极其复杂。

**Natalia**：所以我现在成了 PRD 的粉丝，学会界定范围、尽早判断"买更划算还是自建更划算"。

### Codex 对非技术者的范式颠覆

**核心判断：Codex 把终端、浏览器、视觉模型集成进聊天界面，非技术者不必再想文件系统与脚本设置，只需表达意图即可直接构建运行——架构焦虑被跳过。**

**Natalia**：Codex 是我所知**最伟大的单一改进**。它把终端、浏览器、视觉模型集成进聊天界面，我不必再想文件系统/文件夹/脚本设置，只需表达意图就直接构建运行。过去一年我在学"该学什么才能构建想要的东西"，Codex 让我跳过架构焦虑。

**Dan**：你最让我佩服的是从第一性原理学习的渴求——周末用 Claude/Codex 生成详尽自学指南。

**Natalia**：这是超能力，但也像坏习惯（我真需要从第一性原理学书架史吗？）。不过 Codex 的视觉模型能把学习指南做成卡通漫画，地铁上就能翻——我因此搞懂人体解剖：肌肉变强比韧带快、韧带比骨骼快。

### 个人 AI 技能：从第一性原理到邮件筛选

**核心判断：把个人上下文沉淀为专属 Markdown 与自动化技能，邮件系统就能「比你自己更清楚发生了什么」——每次处理都把经验循环回系统，让它越来越好。**

**Natalia**：我沉迷用 Codex 做"学习技能"——基于最近 150 封邮件训练、理解我的沟通上下文，模仿我的口吻起草便签：可一键批准、要求重写、归档或存进**专属 Markdown 文件**；点任务按钮就变 Asana 任务。每个客户都有专属 Markdown 文件，"我的邮件系统比我自己更清楚发生了什么"。

**Dan**：这就是"循环（Loop）"的典型例子。传统知识工作像雕刻，现在变成**园艺**——你为植物生长创造条件，而非手捏植物。人类做"三明治"的首尾把关，AI 做中间；画流程图处理邮件，每次处理把经验融回系统，使它越来越好。

**Natalia**：这正是你四年前"模型管理者"比喻的演化：从把系统当单点"个人贡献者"，到构建协同运作的系统——像优秀管理者运营庞大团队，为 AI **创造共享上下文环境**。

### 用 AI 构建父亲的健康照护系统

**核心判断：13 小时即可为 81 岁父亲建起护理协作门户——真正好用的工具核心不在工具本身，而在于让家人与护士成为更好的合作伙伴。**

**Natalia**：我用 Codex 花 **13 小时**为 81 岁父亲做了护理协作门户：护士提交 Google 表单、WhatsApp 群同步，中心化"最新动态"概要（西/英一键切换），待办高亮未解决、完成置灰，护士也有只读版保证护理连续性。真正好用的工具核心不在工具本身——护士只觉得我们参与得更主动了，让我们成了更好的合作伙伴。

### 用 Claude Artifacts 探索世界

**核心判断：AI 不只是生成文本，更是更丰富的信息交互方式——随手生成的西语导览与歌单比对筛选，就是探索世界的新接口。**

**Natalia**：带妈妈去新奥尔良，我随手做 Artifacts 生成西班牙语导览；让它读我的 Spotify 歌单，比对法国区艺术节阵容，筛选出最想看的乐队。AI 不只是生成垃圾文本，更是更丰富的信息交互方式。

### 给听众的建议

**核心判断：从你现有的系统开始——把「做好单件事」标准化、定义优秀标准，再处理下一件；最容易犯的错是想直接重构整个体系。**

**Natalia**：从你**现有系统**开始——若已在跟踪 KPI/OKR，直接把这套引导架构交给 AI，想清楚只希望员工做哪些事。最容易犯的错是想直接重构整个体系；其实只需把"做好单件事"标准化、定义优秀标准，再处理下一件，最终攒出复杂系统。最初只需读一个 Markdown 文件或简单说明。

## 限制与边界

- "知识工作=园艺"适用于**信息密集、可结构化**的运营/行政任务；强创造性、需承担人际信任或不确定的判断，仍主要由人做（Natalia 自述人际协作维度不可替代）。
- "该买就买"针对**确定性、规则密集**的成熟软件（CRM/项目管理）；高度个性化、市场上无对应物的工具（父亲护理门户、邮件筛选）才值得自建。
- Codex "跳过架构焦虑"是认知减负，不等于架构不重要；当系统变大、需长期维护时，规则与边界仍要人界定（PRD/范围）。
- "共享上下文"能让系统复利，但上下文质量依赖人类持续提纯信号；若只堆数据不提炼，系统不会自动变好。

## 知识连接

- **支持** [[2026 年 Agent 最重要的工程概念 Harness Engineering]]：Natalia 的 "为 AI 创造共享上下文 + 把流程图/经验循环回系统" 正是 harness 思路——共享上下文环境即 harness 的 source of truth，人定边界、系统跑中间。
- **补充** [[Loop-Agent Loop到底是什么]]：Dan 的 "园艺隐喻 + 人类做三明治首尾、AI 做中间、每次处理把经验融回系统" 正是带人类评分闭环的 loop，对应 "开放式 loop 是 token 焚烧、带评分才合理"。
- **应用** [[Claude Code实战-结合Obsidian打造第二大脑]]：Natalia 为每个客户维护专属 Markdown 文件、把邮件上下文沉淀为可检索知识，与 "用 Markdown 打造第二大脑" 同构，只是载体从 Obsidian 换成 Codex 生成的门户。
