## 4. 迁移演练步骤

### M1：不可变源快照

- 用合成 fixture 建立 vault、入站、Task／Attempt、待决、效果回执、Delivery 和发布映射。
- 计算对象清单与 SHA-256；记录基线，不读取生产正文。
- 验收：源快照在迁移、切换演练和回退后哈希不变。

### M2：迁移计划预检

- 每条活跃事实必须落入迁移矩阵；无法识别或结果未知的记录进入阻断清单。
- 检查重复逻辑键、跨对象引用、旧版本和缺少产物哈希。
- 验收：存在 unknown 或跨对象污染时不得进入可切换状态。

### M3：测试副本导入与重放

- 写入全新测试账本和测试 vault；源目录保持只读语义。
- 重放所有已处理入站、已确认待决和已接受 Delivery。
- 验收：无重复 Task、模型调用、外部发送或发布；对象数量和文件哈希一致。

### M4：在途与未知故障注入

- 分别注入未派发、可恢复、结果未知、待投递、投递 unknown 和部分发布成功。
- 验收：只有明确允许的记录能继续；unknown 不自动重跑或重发；每个阻断项可对账。

### M5：切换窗口入站追踪

- 冻结旧写入和派发，确认旧消费者退出后才启动新测试消费者。
- 在冻结前、窗口内、恢复后各发一条合成事件，记录 Event／Task／Attempt／delivery。
- 验收：三条事件都有唯一归属，没有双消费者或不可解释缺口。

### M6：回退与增量对账

- 生成新期间入站、Task、投递与发布增量；能在旧 Runtime 安全吸收的才回退接管。
- 不能安全逆向的增量保持新侧前向修复，不强行启动旧消费者。
- 验收：回退后对象、去重键、unknown 和外部效果可解释；任何未知项都阻断自动接管。
