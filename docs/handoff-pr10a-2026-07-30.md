## 4. 唯一尚待闭合的代码阻断

Standards 复审在最后一轮指出控制面并发仍需共享 mutation lock：

```text
Home 切换
↔ confirm-test
↔ proactiveDeliveryEnabled=true/false
```

可复现风险：

1. Home 切换 A 先写 `enabled=false` 并开始 cutover。
2. 并发启用请求 B 仍按旧 Home 的有效证据写回 `enabled=true`。
3. A 切到新 Home、清 evidence/testEventId，但没有再次写 `enabled=false`。
4. 最终可能出现 `new Home + enabled=true + evidence=null`。

并发两个 Home 切换也可能都读取同一 `previousHome`，从而遗漏对中间 Home 的 freeze。

接手者应：

1. 在 Runtime 控制面增加一个共享 mutation lock。
2. 在同一锁内串行化 Home 切换、`confirm-test`、主动通知 enable/disable。
3. 每次进入锁后重读当前 Home、release evidence、test event 和 enabled。
4. 增加两个真正并发的回归：
   - enable-vs-switch；
   - switch-vs-switch。
5. 完成后请 Standards 与 Spec 再做一次只读终局复审；不要用测试通过替代复审。

最后一次 Spec 复审确认 Outbox claim、Home barrier、TEST 唯一性等无剩余 P0/P1/P2；Standards 仅保留上述控制面 mutation lock P1。
